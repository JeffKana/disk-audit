# Sprint 规划与任务卡制作（磁盘体检 / PM 角色）

本技能是《[交付与验收流程](../../../docs/governance/交付与验收流程.md)》§6 与《[敏捷开发指南](../../../docs/agile/00_敏捷开发指南.md)》的可执行版。先例：`docs/agile/05_Sprint2_计划与任务卡.md`（卡格式照抄）。

## 五步流程

### 1. 收数

上一 Sprint 的：完成率（有条件通过计 0.5）、退回次数、缺陷与回归集增量、CI 红灯记录、风险看板 R1~R10 止损信号扫描。数据源：验收报告（0N_SprintN_验收报告.md）+ 产品待办列表状态列 + Actions 记录。

### 2. 对表

对照当前里程碑验收口径（方案第七节）与待办剩余条目找差距；里程碑闸门阈值**预先写死**（先例：M1 五闸表、W9 <70% 收缩预案），到点按数据判。

### 3. 排程

优先级 = 里程碑闸门缺口 > 依赖拓扑 > 上轮实际产能。**连续两周完成率 <70% 砍范围不加班**；并行/栈式依赖显式标注（并行卡"无依赖可同时领取"；栈式卡注明"基于 X 分支切出"，先例 T2-03/04 栈于 T2-02）。

### 4. 成卡（DoR 自查后才能发出）

每卡必含字段（《交付与验收流程》§1）：

```markdown
## T<N>-<NN> · <待办ID+名称>（待办 <ID>）
- **目标**：一句话
- **输入指针**：方案节号 + DR + 归档/代码路径（精确到文件）
- **实现约束**：把 W0/历史教训写成硬约束；口径红线指到 DR
- **验收标准**：①②③…每条可执行命令或可测条件（数据类写明口径）
- **依赖**：无 / <卡号>（标注并行或栈式）
- **执行记录**：（留空四项：做了什么/实现决策及依据/未尽事项/自测输出摘要）
```

文件开头放**通用红线**段（不随卡重复）：不 merge/push main、不改验收标准、只写 `%LOCALAPPDATA%\DiskAudit\`、新问题记未尽事项、命令环境注意（指向 exec-sop）。

自查四问：字段齐吗？验收标准可独立判定吗（不依赖"看起来对"）？依赖就绪或已标注吗？单卡 ≤2 天吗（超出先拆）？

### 5. 报批

Sprint 目标一句话 + 打勾清单 + 任务卡包 → 负责人确认 → 分发执行 Agent。负责人改动条目 → PM 重排依赖后再生效。

## 状态回填义务

发卡时同步：产品待办列表对应行状态、Sprint 总览表（00_敏捷开发指南 §里程碑总览）、上一 Sprint 验收报告的"下阶段输入"勾销。

## 与其他技能的边界

验收与数字回填 → accept-verify；卡内技术口径 → 指 DR/方案节，不在卡里复制规则正文；执行 → exec-sop。
