# 规划与任务分派

PM先读[协作契约](references/契约字典.md)，用[模板库](references/模板库.md)写本人持有的task.md。输入为范围、原里程碑阈值、产能/依赖及已交证据；输出为版本化目标、卡片、责任与状态。

1. 汇总已完成、退回、CI与平台故障，事实和未知分开，不编完成率或改变阈值。
2. 按价值/依赖拆卡，标并行与栈序；同文件高风险工作串行或拆文件，不把分支当锁。
3. DoR明确范围、输入版本、可执行标准、风险、执行实例、独测实例、直接退回接收者、PM及授权来源。新流程为开发冻结SHA→独测→QA提PR/报告→CI→PM验收/授权直接合入。缺授权仅补该缺口，既有持续授权不重复问。
4. 逐卡S1指派并要求真实S2；上游或范围变更重新确认，平台ready或超时不自动认领/重派。按项目实际角色登记，不能把新Task当规避失败链的方式。
5. 独测失败可直接回开发并同步PM；PM单点记录任务状态和累计产品退回，同轮只计一次、第二次立即升级。平台启动失败单列，不作产品退回。独测通过/PR/CI/worker_done均是独立事实，不跳过PM最终验收。
6. PM验收与实际合入后更新主状态、待办、风险及条件项，明确下一轮责任与证据。无PR任务按其适用交付标准验收。

状态修改递增revision，不改范围/标准不必改contract_version；契约字典版本与任务契约分列。持续授权有范围和来源，不扩张发布、环境修复或恢复预算。
