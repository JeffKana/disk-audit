# 平台与环境故障运行手册

先读[协作契约](references/契约字典.md)的应急权限、门禁及终验边界；需要复盘时使用[模板库](references/模板库.md)的故障记录。涉及 GitHub API 或 Windows/MSYS 先例时读取[平台排障参考](references/GitHub-故障排查.md)。指定排障实例写自己的记录，向环境基线持有人移交事实；验收与合入记录由各自责任人写入。

## 输入与输出

输入：错误原文、时间、影响范围、当前本地与远端分支/head、待完成操作。输出：可复现的故障分级、探测结果、处理或升级记录、环境事实和接收确认；不保证故障可在固定时间内恢复。

## 排查与恢复

1. 区分单命令/传输失败、推送已到但事件管道未更新、站点与 API 端点可达性不同、完全不可达、本地工具链/编码故障。比较 branch、PR 和检查记录；避免凭单一缓存响应推断状态。
2. 仅在授权范围内做有界探测和重试，按实际环境考虑 SSH、HTTPS、平台 API 或已批准代理；记录每次尝试。若全部不可用，保留本地命名分支或其他安全锚点并升级，不基于过期默认分支解突。
3. 若项目允许 API 应急通道，先确认独测报告/PR、当前必需CI和PM验收、最新远端基线，以及已登记持续合入授权；不以环境恢复增加重试预算或发布权限。使用平台文档核实受保护分支、API 和权限；只更新获准的工作分支，不对默认分支强推。提交变化后重新验证当前 head 的验收与必需 CI；事件未触发或仍红灯则暂停，不合入。
4. 获授权合入后由合入责任人写独立记录，包含 PR、实际 head、必需检查、授权和结果；若下载受阻，可按契约的限制对比已测树与远端树，LFS、子模块和未跟踪内容需另验。
5. 写时间线、根因/未定项、尝试、门禁偏差、恢复结果和剩余风险；脱敏后交基线持有人确认并回填。对可复用的通用知识由包维护者评审后更新本手册，项目事实不直接写回共享技能。

## 平台先例

GitHub 上 branch tip 已更新但 PR head/check 未更新时，要分别核对 API 结果及实际检查；API 可达也不代表必需 CI 已完成。Windows/MSYS 中编码、PATH、代理与命令行长度可能影响工具；先复现并确认，勿把先例当作所有环境的根因。
