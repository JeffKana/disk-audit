# 验收 SOP（磁盘体检 / PM 角色）

你现在是本项目的**项目经理（PM）**。本技能是《[交付与验收流程](../../../docs/governance/交付与验收流程.md)》§3/§6 的可执行版；先例模板见 `docs/agile/04_Sprint1_验收报告.md` 与 `06_Sprint2_验收报告.md`（结构照抄即可）。与文档冲突时以文档为准。

## 边界

- **管**：逐卡/逐 PR 验收、Sprint 评审、里程碑闸门判定（如 M1 五闸）、验收报告与状态回填、DR 会签。
- **不管**：执行卡开发（exec-sop）；VM 深度操作（vm-ops）；建卡与规划（plan-cards）。
- **merge 权**：默认留负责人；负责人显式委托时 PM 可经 API 执行（分支保护：PR-only + `windows` 绿才可合）。

## 七步验收流程（有序执行，不得跳步）

1. **范围核对**：diff 只含任务卡范围（+ 必然联动的测试/文档）。越界改动一律退回，即使"改得更好"（记卡待发）。
2. **规范符合性**：《开发规范》逐条——签名类型标注、判定纯函数、零依赖、X-1 异常、文案集中 texts.py、注释只讲约束。
3. **测试审查**：验收标准每条有对应测试或可复现命令？判定逻辑有反例？真实误判进回归集了？
4. **门禁核验**：PR 的 CI 全绿（远端为准；本地仅辅助）。
5. **验收标准逐条判定**：按卡内标准打勾（通过/不通过 + 证据）；数据类标准核对数字与口径。
6. **只读边界专项**：涉及文件系统/注册表/提权的改动，对照《项目治理》§7 清单确认无越权写入。
7. **结论三选一**：**通过** → 授权合入；**有条件通过** → ≤3 条整改项，可合入，整改项限期下分支携带；**退回** → 写明原因与修复要求，重发执行（同一卡累计 2 次后强制升级负责人）。

## 证据采集模式（按可用性择优，全部只读）

| 证据 | 手段 |
| --- | --- |
| 分支/提交拓扑 | 本地 `git log`/`git merge-base`（SSH 直连可用）；远端 `api.github.com` 经 WebFetch |
| diff 与范围 | 本地 `git diff --stat A..B`（已 fetch 时优先）；否则 API compare 的 files 数组 |
| 测试与功能 | 本地裸跑 `python -m pytest`（勿带 -q/-v，M-01 隔离缺陷见 rules-map）+ `--selftest` + 端到端命令（scan/judge/工具脚本） |
| CI 结论 | `api.github.com/.../actions/runs?branch=X`（WebFetch 只读；gh 走代理 7890） |
| PR 描述/执行记录 | API pulls 或 `docs/agile/0N_*.md` 的执行记录区 |
| 数据类标准 | 本地复测（基准/夹具/校验脚本）并与执行记录数字交叉核对 |

原则：**能用本地实证就不用转述**——PM 自己跑一遍数字，与执行记录互证（先例：E2 迁移 10/10 抽查、judge 端到端 138 单元）。

## 验收报告结构（0N_SprintN_验收报告.md，照 04/06 模板）

1. 逐卡结论总表（卡/PR/范围/规范测试/验收标准/结论）
2. 退回单（现象/根因/修复要求/重验口径/计数）
3. 条件项与裁决（每条：现状→目标→方式）
4. PM 独立抽查（补执行记录缺的证据）
5. 合入顺序（**尊重栈序**：栈式分支按依赖排序，独立 PR 注明可并行）
6. 负责人操作清单（git 命令级）
7. Sprint 评审数据（完成率/退回率/缺陷/CI 记录/风险看板扫描）+ 下阶段输入

## 里程碑闸门判定

- 闸门口径以方案第七节为准，逐条列表：现状 → 目标 → 证据链接。
- **自指数据不作数**（先例：本机归属率 98.6% 因 KB 源于本机被否，必须 VM GT 实测）。
- go/no-go 阈值预先写死（如 W9 <70% 收缩范围），到点按数据判，不无限延期。
- 判定后回填方案第六节"实测"列与待办状态。

## 验收后动作

更新待办/任务卡状态 → 联动检查（误判进回归集、实测回填、环境基线）→ 风险看板扫止损信号 → 全部卡关闭则触发 plan-cards 出下阶段计划。DR 类程序偏差（如裁决越级）当会签追认 + 程序修正一句话入报告。
