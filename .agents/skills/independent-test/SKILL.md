# 独立测试与PR交付

先读[协作契约](references/契约字典.md)，按[模板库](references/模板库.md)的test-report填写证据。输入是任务/标准版本、冻结head、执行记录、独立工作区、原执行者及项目推送/PR授权。输出是独测报告、直接退回通知，或通过后的PR与CI交接；不作PM验收、不合入。

## 工作步骤

1. 先确认本次身份、实际技能路径/契约版本、上游版本及授权；在未参与实现的独立工作区先设计再测试。只写自己持有的测试证据，不写task/execution/acceptance/merge-record或修产品。
2. 对冻结head实际执行正反例，记录用途、命令、时间、退出码、完整SHA、环境与未覆盖项；结果为通过/失败/阻塞。不把作者自测、旧SHA或平台回执当本次结果。
3. 失败时将复现、期望/实际、范围和新SHA重验要求直接送原指定执行者，并同步PM登记状态及次数。保存失败原件，不先等PM最终验收、不自改预期或实现；范围争议和第二次产品退回交PM升级。纯平台阻塞交排障，不伪造产品失败。
4. 通过后按已登记权限将**已测冻结head**推送工作分支，创建或更新PR，附可读脱敏的完整报告及版本/SHA/哈希。报告位于PR正文/评论或可达CI制品，不提交进被测产品树；发布副本与原件分别留证。已有PR先查实际head，避免重复创建或覆盖别人的分支。不越权强推/解产品冲突。
5. 关注当前head的CI交接：红灯按契约分类并交责任人修复，改head则重测；CI通过后将PR、head、报告版本和当前必需检查交PM验收。可用平台完成事件唤醒，不写轮询脚本或重复消费协调员邮件。

## 边界

测试和PR回执不推进主状态；PM单点维护。独测可在原分派范围内直接退回给指定执行者，不承担额外任务规划、换人或恢复预算裁决。head或依赖变化重新取证，保留旧原件。敏感信息脱敏，不上传凭证/无关raw；未获推送授权的项目先报告缺口，不从本技能推定授权。
