# 开发实现与修复

先读[协作契约](references/契约字典.md)，标准/高风险使用[模板库](references/模板库.md)的execution。仅写分派的实现、测试和自己的执行证据；不改任务标准、独测报告或PM验收/合入制品。

1. 核本次实例、任务/字典版本、范围、依赖、权限及写入者，按S1/S2/S3确认后执行；冲突停报PM。
2. 阅读方案与源码，按风险测试先行，维护可重复正反例与I/O边界；明确基线、分支及栈序。
3. 实现并运行适用测试、自检及门禁，记录命令/退出码、限制、决策与未尽项。不把自测当独测或远端CI。
4. 本地提交后冻结完整SHA，交指定独测实例及PM。独测通过后由独测实例负责推送工作分支/建PR附报告，开发侧不抢建第二个PR；项目另有明确约定时按其执行。
5. 接收独测或CI直接退回时，确认失败SHA、复现、修复范围与谱系，只在原任务授权范围修复；新SHA交同一独测流程。新增范围/争议交PM，不等于可自改标准；旧失败原件不覆盖、不amend掩盖历史。

执行记录含完成内容、实现决策/依据、未尽事项/风险、自测证据及待验head。新的head不得借旧QA/CI；CI归因交ci-cd-ops，环境故障交ops-runbook；执行者不合入或发布。
