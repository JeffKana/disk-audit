## 2. 退回单：T-01（A4 import 白名单）—— ✅ 已闭环（2026-10-25 PM 复验通过）

**复验记录**：修复提交 `eaa83c7` 范围与退回单授权完全一致（3 文件 +46 行：`_force_utf8_stdio()` 带 hasattr 守卫 + ci.yml 顶层 `PYTHONUTF8: "1"` + 回归用例）；回归用例 `test_gate_survives_non_utf8_stdout` 以 `PYTHONIOENCODING=cp1252` 子进程复现 runner 场景（该变量优先级高于 PYTHONUTF8，复现有效），双断言（干净树 0 / 违规树 1）确保门禁语义不漂移；CI 对 eaa83c7 重跑 **success**（2026-10-25T02:24:48Z）。**结论：T-01 转"通过"，授权合入 PR#2；退回计数定格 1/2。** 执行侧同时上报的 DR-004 极小文件驻留问题已裁决为 DR-004 修订（见 decisions/DR-004 修订节）。

- **现象**：PR #2 的 CI 第 8 步"import 白名单门禁"失败，瞬间退出（16:40:31Z 同秒）；同 run 内 pytest/selftest 全绿。
- **根因（PM 定位）**：`tools/check_imports.py` 所有输出含中文；GitHub windows runner 上 Python 3.13 的 stdout 默认编码为 cp1252（PEP 686 的 UTF-8 默认自 3.15 才生效），`print` 中文即抛 `UnicodeEncodeError` → 进程退出码非 0 → 门禁红。与白名单判定逻辑无关（判定逻辑审查通过：默认根经 `__file__.parents[1]` 解析正确、`sys.stdlib_module_names` + 包内白名单正确、相对导入/解析失败处理正确）。
- **修复要求（二选一，建议 a+b 双保险）**：
  - a. 脚本入口处 `sys.stdout.reconfigure(encoding="utf-8")`（对 stderr 同样处理）；
  - b. ci.yml 该步骤加 `env: PYTHONUTF8: "1"`（或 workflow 顶层统一设置，顺带保护未来含中文输出的步骤）。
- **重验口径**：修复提交推回同分支 → CI 全绿 → PM 复验第 4 步后转"通过"。**不占用退回计数上限（现为 1/2）。**
