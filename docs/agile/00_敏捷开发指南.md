# 磁盘体检 · 敏捷开发指南

把《[磁盘体检 v0.1 方案（定稿）](../upstream/磁盘体检_v0.1方案_定稿_2026-10-23.html)》的 M1~M5 里程碑，转成"单人 + AI 辅助"可执行的敏捷节奏。本指南定义节奏、仪式、完成定义（DoD）与变更管理；需求内容以方案定稿为唯一基线，本文档只管"怎么跑"，不重新定义"做什么"。

## 1. 节奏与角色

| 项 | 约定 |
| --- | --- |
| 角色 | 项目负责人（你）＝产品负责人＋开发＋测试；AI＝结对编程／评审／回归执行 |
| Sprint 长度 | 1 周，共 12 个（S1~S12），对齐方案 W1~W12 |
| 里程碑映射 | M1＝S1~S2（引擎）· M2＝S3~S4（可用）· M3＝S5~S6（体检闭环）· M4＝S7~S9（准发布）· M5＝S10~S12（开源发布） |
| Sprint 0 | 一次性工程准备（仓库骨架、CI 初版、文档体系），2026-10-24 已启动 |
| 需求基线 | 方案定稿 F1（2026-10-23），状态"无待决策项"；变更必须走第 4 节流程 |

## 2. 仪式（单人版，每周固定动作）

- **Sprint 计划**（周一，≤30 分钟）：从[产品待办列表](01_产品待办列表.md)拉取条目，写下本周 Sprint 目标（一句话）与验收清单（可打勾）。
- **每日检查**（5 分钟，可与 AI 对话代替）：昨天完成什么／今天做什么／有什么阻塞。
- **Sprint 评审**（周五）：逐条核对本周验收清单；里程碑所在的 Sprint 末尾，追加按方案第七节该里程碑验收口径过闸（全过才算里程碑完成）。
- **回顾**（评审后 15 分钟）：保持／停止／尝试三件事；记录到本文件末尾的"回顾日志"。
- **回归底线**（随时）：任何真实误判当天转化为回归测试用例（方案 9.1 底线二）。

## 3. Definition of Done（每条故事的完成定义）

1. 代码合入主干，`pytest` 全绿；CI 流水线（`import tkinter` 断言 → pytest → 构建 → `--selftest` 门禁）通过。
2. 新增判定逻辑有对应测试；若本周发现真实误判，回归集当天新增用例。
3. 运行时零第三方依赖不被破坏（CI 的 import 白名单校验通过；site-packages 无第三方包进入产物）。
4. 只读边界不破坏：代码自身仅在 `%LOCALAPPDATA%\DiskAudit\` 写入（U-2）。
5. 知识库、文档、变更记录同步更新。
6. 对应的 EARS 条目可独立验收演示（方案第三节 U/E/S/X 编号）。

## 4. 需求变更管理

- 方案定稿是范围基线：**不接受口头扩范围**。任何变更先评估对 R1~R10 风险与排期的影响，写入方案第十三节变更记录，再进待办列表。
- 三条不可协商底线不接受变更（方案 9.1）：硬保护先于一切判定；误判当天进回归集；宁可漏报不可误报。
- 每个里程碑末做一次 go/no-go：M4 的 W9 检查点为"自动归属率 < 70% → 范围收缩到 AppData、发布延后"（方案第七节）。

## 5. 风险看板（每 Sprint 评审过一遍止损信号）

完整风险登记册见方案第十节（R1~R10）。评审时重点盯两条高优先级：

| 风险 | 当前状态 | 止损信号 → 动作 |
| --- | --- | --- |
| R2 未签名被杀软/SmartScreen 拦截（中高/高） | M0 本机 Defender 无告警；VirusTotal 留档未做（U1/U3） | ≥3 家主流杀软持续拦截 → 主推源码运行，安装包标实验性 |
| R5 误判诱导用户删错（中/极高） | 原型已知 1 例子串误判，已修复待入回归集 | 任一高置信误判 → 立即降级该规则并全量复核同类规则 |

## 6. 度量

- **Sprint 燃尽**：计划故事数 vs 完成故事数（连续两周 < 70% 需砍范围而非加班）。
- **质量门**：pytest 通过率、回归集规模、（M4 起）VM 自动归属率与高置信误判数。
- **性能回填**：每个里程碑末，把实测值回填方案第六节"实测"列（容量偏差、归属率等验收数据）。
