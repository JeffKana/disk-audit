# 交付与验收流程（磁盘体检 / disk-audit）

定义"任务从立项到关闭"的完整闭环：**任务卡（DoR）→ 执行（SOP）→ 交付（PR）→ 验收（SOP）→ 决策 → 下一阶段计划**。本文是项目经理与执行 Agent 之间的交接契约；敏捷节奏（Sprint/仪式）见《[敏捷开发指南](../agile/00_敏捷开发指南.md)》，门禁见《[CI/CD 规范](CI-CD规范.md)》。

## 0. 角色与职责

| 角色 | 承担者 | 职责 | 不做 |
| --- | --- | --- | --- |
| 负责人 | 人 | 计划审批、资源、merge PR、发布、范围/排期/风险终审 | 不直接编码 |
| 项目经理（PM） | 验收 AI | 制定 Sprint 计划与任务卡、治理维护、**验收交付物**、里程碑把关、制定下一阶段任务 | 不 merge、不扩范围、不代替执行 |
| 执行 Agent | 执行 AI | 按任务卡开发、自测、交 PR | 不 merge/push main、不改范围、不越任务卡半步 |

## 1. 任务就绪标准（Definition of Ready）

PM 发出任务卡前自查，不满足不发：

1. 卡内字段齐全：待办 ID、目标（一句话）、输入指针（方案节号 + 归档/代码路径）、实现约束、**验收标准（可执行命令或可测条件）**、依赖、禁止事项、执行记录区。
2. 验收标准可独立判定（不依赖"看起来对"）；涉及数据的写明口径（如"占用空间口径、与资源管理器对比"）。
3. 依赖项已就绪并在卡中标注（依赖未完成的任务不发，或标注"可与 X 并行"）。
4. 范围单卡可关闭（≤2 天工作量）；超出的先拆卡。

## 2. 执行 SOP（执行 Agent 拿到任务卡后的标准动作）

1. **先读后做**：读任务卡 → 方案对应节 → 《开发规范》《项目治理》相关条款 → 依赖模块代码。有任何一项与任务卡冲突，**停下来回报冲突，不自行取舍**。
2. **确认依赖**：依赖未就绪 → 在执行记录区标"阻塞：依赖 xxx"并回报，不得顺手先做依赖项之外的事。
3. **建分支**：`feature/<待办ID>-<短横线摘要>`（治理 §2）。
4. **测试先行**（判定类逻辑）：先写/补测试用例（含反例），跑红，再实现，跑绿。
5. **编码**：遵守开发规范 §1~§3（类型标注、纯函数、零依赖、异常按 X-1、文案集中）。
6. **自测**：本地跑 `pytest` 与 `--selftest`（完整解释器路径），输出摘要贴进执行记录。
7. **回填执行记录**：做了什么、关键实现决策（及依据）、未尽事项/已知限制、自测输出摘要。
8. **交 PR**：Conventional Commits + 中文描述；PR 描述 = 任务卡验收标准逐条 + 自测结果；注明"AI 辅助生成，待验收"。
9. **红线**：不 merge、不 push main、不改任务卡验收标准、不改 .github/workflows、不动 `%LOCALAPPDATA%` 之外的写入逻辑、发现新问题记入"未尽事项"而不顺手修（另立任务）。

## 3. 验收 SOP（PM 的验收流程，按序执行）

1. **范围核对**：diff 只含任务卡范围（+ 必然联动的测试/文档）；越界改动一律退回，即使"改得更好"（记卡待发）。
2. **规范符合性**：开发规范逐条过——签名类型标注、判定纯函数、零依赖、异常处理、命名与文案、注释是否只讲约束。
3. **测试审查**：验收标准每条都有对应测试或可复现命令？判定逻辑有反例？硬保护正反例齐？真实误判进回归集了？
4. **门禁核验**：PR 的 CI 全绿（阶段 A~B 门禁）；红灯的 PR 不进入后续步骤。
5. **验收标准逐条判定**：按卡内标准逐条打勾（通过/不通过+证据）；数据类标准核对数字与口径。
6. **只读边界专项**：任何涉及文件系统/注册表/提权的改动，确认无越权写入路径（治理 §7 清单）。
7. **结论**（三选一）：
   - **通过** → 通知负责人 merge（§4）。
   - **有条件通过** → 小瑕疵不影响验收标准（如命名、注释），列 ≤3 条整改项，可 merge，整改项转微任务卡下 Sprint 修。
   - **退回** → 违反验收标准/规范红线/越界；退回原因写入任务卡，重发执行。

## 4. 验收通过后的动作与决策

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 负责人 merge PR（CI 已绿） | 代码进 main |
| 2 | PM 更新[产品待办列表](../agile/01_产品待办列表.md)状态、Sprint 计划勾选、任务卡标"已关闭" | 状态同步 |
| 3 | PM 检查该条目触发的联动：误判案例→回归集；实测数据→方案第六节；环境变化→环境基线 | 数据回填 |
| 4 | PM 复查风险看板（R1~R10 止损信号） | 风险状态 |
| 5 | Sprint 内全部条目关闭 → 触发 §6 下一阶段制定；里程碑末 Sprint 额外走里程碑验收（方案第七节口径） | 里程碑判定 |

## 5. 决策机制与防死胡同

**决策分级**（谁决定什么）：

| 级别 | 内容 | 决定者 |
| --- | --- | --- |
| D-执行 | 实现细节（算法、结构、命名），不违反任何规范 | 执行 Agent 自决，记入执行记录 |
| D-技术 | 偏离选型、模块接口变更、验收标准歧义 | PM 裁决（当日），必要时建 DR |
| D-项目 | 范围增减、排期调整、风险接受、资源 | 负责人裁决 |

**四条防死胡同机制**：

1. **返工上限**：同一任务卡退回 ≤2 次；第 3 次强制升级负责人，选项只有三个——换实现方案 / 拆解重发 / 冻结该条目调整 Sprint 范围。禁止无限返工循环。
2. **裁决时限与保守默认**：升级后 48 小时未裁决，按"保守默认"推进（与方案 9.1 底线三同向：宁可漏报不可误报、宁可少说不可多说），事后补决策记录。
3. **数据裁决**：技术争议不空谈，以测试/VM 实测数据为准（口径按方案 9.2）；拿不出数据的争议方承担"待数据"状态，不阻塞其他条目。
4. **预设 go/no-go**：里程碑闸门口径在方案第七节预先写死（如 W9 归属率 <70% → 收缩范围），到点按数据判，不做无限延期。新增闸口阈值须先入 DR。

## 6. 下一阶段任务制定流程（每 Sprint 末，PM 执行）

1. **收数**：Sprint 完成率、退回率、缺陷与回归集增量、CI 红灯记录、风险看板止损信号扫描。
2. **对表**：对照当前里程碑验收口径（方案第七节）与待办列表剩余条目，找差距。
3. **排程**：按"里程碑优先级 + 依赖拓扑 + 上轮实际产能"拉取条目；连续两周完成率 <70% 则砍范围不加班（敏捷指南 §6）。
4. **成卡**：逐条做 DoR 自查，产出下一 Sprint 任务卡（含验收标准）。
5. **报批**：Sprint 计划 + 任务卡包交负责人确认 → 分发执行 Agent。负责人改哪条，PM 重排依赖后再生效。
