# 环境基线（2026-10-24 探测定稿）

本机开发与验收环境的权威记录。探测方法：文件系统标记与资源查询（只读），未修改系统任何配置。环境变化时更新本文件并在变更记录登记。

## 1. 结论速览

| 项 | 结论 | 影响 |
| --- | --- | --- |
| Windows 版本 | Win11 x64，Pro 级（`lusrmgr.msc` 存在；方案支持矩阵 22H2+ 此前已实测） | **支持完整 Hyper-V**（Home 版才受限） |
| Hyper-V 功能 | **未安装**：`vmms.exe` 与 Hyper-V PowerShell 模块不存在 | M1 验收（VM 矩阵）前必须先启用 |
| CPU 虚拟化 | 已开启：WSL2/HCS 在用（`vmcompute.exe` 存在，机器上有 Docker/WSL 使用痕迹） | 启用 Hyper-V 无 BIOS 障碍 |
| 内存 | 32GB（MemTotal 33,289,592 kB） | 足够同时跑 2 台 4~6GB 的 Win11 VM |
| 磁盘 | C 剩 20G（90% 用）/ D 剩 13G（88% 用）/ **E 剩 40G**（79% 用） | VM 磁盘只能放 E 盘；见 §3 预算 |
| 第三方虚拟机软件 | 未发现 VMware Workstation / VirtualBox 安装 | 无共存冲突顾虑（Local\VMware 仅为配置残留） |
| Python | 本机 `python` 命令指向 Windows Store 存根（执行挂起）；实际开发用 W0 POC 的 CPython 3.13.5（含 Tcl/Tk 8.6） | 开发/CI 命令一律用完整解释器路径；CI 用 setup-python 不受影响 |

## 2. Hyper-V 启用步骤（负责人执行，一次性）

1. 以管理员身份运行 PowerShell，执行：
   ```powershell
   DISM /Online /Enable-Feature /All /FeatureName:Microsoft-Hyper-V /NoRestart
   ```
   （等价图形操作：`OptionalFeatures.exe` 勾选"Hyper-V"全部子项。）
2. 重启系统。
3. 重启后验证（管理员 PowerShell）：
   ```powershell
   Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All   # State 应为 Enabled
   Get-VM                                                                    # 应无报错返回空列表
   Get-Service vmms                                                         # 状态应为 Running
   ```
4. 验证通过后：更新本文档状态、勾销 Sprint 0 任务 0.7。

**已知影响与风险**：
- Docker Desktop / WSL2 不受影响（同用 HCS 底座）。
- 旧版 VMware Workstation（<15.5.5）与 Hyper-V 不兼容——本机未装，无此风险。
- 启用后 CPU 进入 Hypervisor 模式，游戏/反作弊个别场景性能略降；如遇问题可用 `bcdedit /set hypervisorlaunchtype off` 临时关闭（会同时停用 WSL2/Docker，验收期勿关）。

## 3. VM 磁盘预算（差分盘方案）

约定目录：**`E:\Virtual Machine\disk-audit\`**（软件安装仍按你的习惯放 `D:\develop\software`；Hyper-V 管理工具随系统功能安装，不占该目录）。

> 说明：你答复中提到 "Virtual Machine" 目录；D 盘仅剩 13G，装不下两个 Win11 父镜像（实际各占 15~25G），故默认放 E 盘（剩 40G）。坚持 D 盘需先清理出 ≥40G 并更新本节。

| 资产 | 数量与体积（动态 VHDX 实际占用估算） | 说明 |
| --- | --- | --- |
| 父镜像 `base-22h2.vhdx` | 1 × ~18G | 全新安装 + 系统更新至最新 + 关机前 `Optimize-VHD` 压缩 |
| 父镜像 `base-24h2.vhdx` | 1 × ~18G | 同上 |
| M1 验收机差分盘 | 2 × 5~8G | 每台 4GB 内存、2 vCPU；父镜像设为只读 |
| **M1 合计** | **约 46~52G 峰值** | E 盘 40G 略紧：先建 24H2 全套 + 22H2 父镜像，22H2 差分机在 24H2 验收后创建；或清理 E 盘 ≥15G 一次到位 |
| M4 扩展（S7~S9） | 8 台差分盘滚动创建/销毁 | 不同软件组合 = 不同差分子代；ground truth 装N卸M后打快照，验收后回收 |

**硬约束**：VM 磁盘文件（`*.vhdx`/`*.vhd`）永不进 git（`.gitignore` 已排除）；M1 前若 E 盘可用空间 < 30G，先清理再建镜像，不得压缩父镜像牺牲可复现性。

## 4. 探测方法存档（复现本结论）

- Pro 判定：`C:\Windows\System32\lusrmgr.msc` 存在（仅 Pro/Enterprise/Education 分发）。
- Hyper-V 未装：`C:\Windows\System32\vmms.exe` 不存在 + `C:\Windows\System32\WindowsPowerShell\v1.0\Modules\Hyper-V\` 不存在。
- HCS 在用：`C:\Windows\System32\vmcompute.exe` 存在（`hvax64.exe`/`hvix64.exe` 系统自带，不构成 Hyper-V 已启用证据）。
- 资源：`df -h` 与 `/proc/meminfo`（Git Bash）。
