# 开发规范（磁盘体检 / disk-audit）

配合《[项目治理](项目治理.md)》使用；对代码与测试的具体要求以本文为准。

## 1. Python 代码规范

- **版本与依赖**：CPython 3.13.x（构建机 3.13.5，须含 Tcl/Tk 8.6）。**运行时零第三方依赖**（仅标准库）；开发期唯一第三方依赖为 `pytest`。
- **风格**：PEP 8；行宽 100；用 `from __future__ import annotations` 保持前向兼容写法。
- **类型标注**：公共函数与判定层（`engine/`、`hardprotect` 等）**全部签名强制类型标注**；UI 层鼓励标注。
- **判定纯函数**：归属判定逻辑必须为纯函数（输入路径/证据 → 输出判定，无 I/O、无全局状态）；I/O 采集与判定分离，保证可测试与可回放。
- **模块解耦**：引擎与 UI（Tkinter）严格分离；`disk_audit` 包内任何模块不得 import `tkinter`（启动器在独立模块/入口，CI 用 import 白名单校验）。
- **docstring**：中文，模块头写明依据（方案节号/待办 ID）与约束；不写"改动说明"类注释。
- **错误处理**：枚举类异常一律按 X-1 处理（跳过 + 计数 + 继续），禁止让单点失败中断全盘扫描。
- **命名**：模块/函数英文小写下划线；对外文案（报告、UI、异常提示）中文，集中在文案资源处，不散落硬编码。

## 2. 零依赖白名单机制

- 运行时 import 仅允许：标准库 + `disk_audit.*`。
- CI 门禁（Sprint 1 落地，A4）：扫描 `disk_audit/` 的 import 语句对照白名单；打包产物中不得出现 site-packages 第三方包。
- **增补流程**：确需新增运行时依赖 → 新建 DR 决策记录 → 更新方案定稿变更记录 → 才可修改白名单。此流程同样适用于"标准库模块冷门入口"的加入（如 `winreg` 之类平台专属模块属预期内，登记即可）。

## 3. 测试规范

- 框架 pytest；测试放 `tests/`，命名 `test_<模块>.py`；参数化优先于重复用例。
- **硬保护规则 pytest 覆盖 100%**（M1 验收③），新保护规则必须同时交正反用例。
- **真实误判当天进回归集**（底线二）：每例包含——路径样例、期望判定、实际误判、根因、修复链接；回归样例 JSON 一律脱敏（不含用户名/机器名/SID）。
- 判定类测试以"判定样例 JSON + 期望输出"数据驱动，样例文件与测试分离，便于 W0 原型 500 行 CSV 逐步迁移为 ground truth。
- 性能相关（扫描耗时、报告首屏）不在单测断言，进入里程碑验收脚本（L2/L4），避免 CI 抖动。

## 4. Git 与提交规范

- 提交信息：Conventional Commits 前缀 + 中文描述，如 `feat(C2): 文件枚举器 8 线程前沿切分`、`fix(D6): 限定包含匹配仅限含点号包名`、`docs(agile): Sprint 1 评审记录`、`chore(ci): 接入构建门禁`。
- 一次提交对应一件事；禁止"顺手"夹带无关文件。
- 合入走 PR（治理 §2）；提交前本地必跑：`pytest` 与 `--selftest`。
- **本机注意**：`python` 命令为 Windows Store 存根（挂起），所有命令使用 W0 POC 那套 CPython 3.13.5 完整路径执行。

## 5. CI 门禁（定义与失败处置）

| 门 | 内容 | 失败处置 |
| --- | --- | --- |
| ① tkinter 断言 | `python -c "import tkinter"`（C4 教训：缺失只在运行时暴露） | 检查 runner Python 是否含 Tcl/Tk，不得跳过 |
| ② pytest | 全部单元测试 | 修复后重跑；禁止删用例绿灯 |
| ③ `--selftest` | 内置自检退出码 0 | 同上 |
| ④ import 白名单（S1 接入） | 运行时零第三方依赖 | 移除违规 import 或走 DR 流程 |
| ⑤ 构建 + 产物自检（S2 接入） | PyInstaller onedir；产物内 tkinter 断言 + 产物 `--selftest` | 检查构建解释器（C4：缺 Tcl/Tk 构建日志不报错） |

- 门禁红灯的分支不得合入；main 出现红灯当天修复优先级最高。
- CI 文件变更本身也要走 PR。

## 6. AI 协作守则

- AI（执行 Agent）产出的代码、文档、知识库条目按《[交付与验收流程](交付与验收流程.md)》走：自测跑绿 → 提 PR（注明"AI 辅助生成，待验收"）→ 项目经理验收 → 负责人 merge。
- AI 不得执行：git push、发布、提权操作、删除性命令；不得自行扩大方案范围。
- **命令拆小**（WorkBuddy 实测教训）：超长单行 PowerShell/Shell 命令会被安全层拦截或挂起，拆成多条短命令执行。
- **命令通道优先 pwsh**（负责人 2026-10-24 约定）：需要执行 PowerShell 时优先 `pwsh -NoProfile -NonInteractive`（位于 `C:\Program Files\PowerShell\7\pwsh.exe`）；避免依赖 Windows PowerShell 5.1 与超长内联命令。
- 本会话已知环境限制：AI 会话的 Git Bash 沙箱中**任何原生 Windows exe（git/python/py/cmd/pwsh）启动即挂起**（与项目目录中文命名无关，已在 ASCII 目录下对照复现）；MSYS 工具（ls/cp/mv/find/df/md5sum）正常。因此：AI 侧文件操作用 MSYS 工具与专用工具完成；涉及原生 exe 的验证步骤由负责人终端执行，AI 提供命令清单。**项目目录不因该问题改名**（改名无济于事且破坏会话绑定）。
- AI 生成内容中引用的数据（性能数字、结论）必须能追溯到方案定稿或归档物，不得凭空给出。

## 7. 文档维护义务

- 代码变更影响行为时，同步更新：方案变更记录（范围级）、待办列表状态、模块 docstring 中的方案节号引用。
- 报告与体检记录的数据结构带 `schema_version`；结构变更必须升版本号并处理旧版兼容提示（Q7），禁止原地改义。
- 每个里程碑末回填方案第六节"实测"列（敏捷指南 §6 度量）。
