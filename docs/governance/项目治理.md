# 项目治理（磁盘体检 / disk-audit）

本文件是项目的治理总纲：仓库怎么组织、变更怎么走、版本怎么发、知识库怎么管、安全底线怎么守。需求与范围以《[v0.1 方案定稿](../upstream/磁盘体检_v0.1方案_定稿_2026-10-23.html)》为唯一基线；过程节奏以《[敏捷开发指南](../agile/00_敏捷开发指南.md)》为准；本文管"项目怎么治理"。冲突时以方案定稿 > 本文件 > 其他文档为序。

## 1. 仓库与目录

| 位置 | 职责 | 约束 |
| --- | --- | --- |
| `disk_audit/` | 引擎与 CLI | 判定逻辑纯函数、零 UI 依赖、可独立 CLI 调用 |
| `tests/` | pytest 测试 | 见《[开发规范](开发规范.md)》 |
| `knowledge/`（Sprint 1 建立） | 知识库数据 | 全部自行整理，见 §6 |

| `docs/governance/` | 治理与规范、决策记录 | 变更走 §4 |
| `docs/upstream/` | **上游资料唯一归档入口** | 新增材料必须入此并登记其 README |
| `.github/workflows/` | CI | 门禁定义见开发规范 §6 |

- 二进制与构建产物**不进 git**（`.gitignore` 排除 `*.exe`、`*.vhdx`、`*.vhd`、`docs/upstream/poc/build|dist`）。
- 远端仓库：`https://github.com/JeffKana/disk-audit.git`，默认分支 `main`。

## 2. 分支与合入（定稿：短分支 + PR）

- **main 受保护**：所有变更经 PR 合入；要求 CI 绿灯方可合并；禁止 force push；单人项目由负责人自审合并。
- **分支命名**：`feature/<待办ID>-<短横线摘要>`（如 `feature/C2-文件枚举器`）、`fix/<待办ID或issue>-<摘要>`、`docs/<摘要>`、`chore/<摘要>`。
- **分支生命周期**：一个分支承载一个待办条目（或一组不可拆分的小条目），目标 1~3 天内合入，不超过一个 Sprint。
- **PR 要求**：描述写明对应待办 ID 与验收要点；逐条对照 DoD（敏捷指南 §3）；带测试的判定逻辑须贴出本地 `pytest` 与 `--selftest` 输出摘要。
- 里程碑所在的 PR（如 M1 验收脚本）额外附验收数据（偏差值、归属率等）。

## 3. 版本与发布

- 版本从 **0.1.0** 起，语义化版本（方案 P9）；开发期用 `0.1.0.devN`，预发布用 `-beta.N`。
- `disk_audit/__init__.py` 的 `__version__` 为唯一版本来源；发布时同步打 git tag `vX.Y.Z`。
- **发布 checklist**（M5 起执行，逐项留档）：
  1. CI 四段门禁全绿；回归集通过率 100%。
  2. `pyproject.toml` / `__version__` / tag 三处版本一致。
  3. portable zip + 安装包 + `SHA256SUMS` 三件套齐备。
  4. VirusTotal 记录（普通版 + 提权版，遗留动作 U1/U3）与干净机 SmartScreen 提示记录（U2）已留档。
  5. Release 页含"已知限制"清单与英文简版说明。
  6. README 免责声明、"未知发布者"告知在位。

## 4. 变更管理

- **范围变更**：先评估对 R1~R10 与 12 周排期的影响 → 写入方案定稿第十三节变更记录 → 更新产品待办列表 → 方可实施。
- **三条不可协商底线**（方案 9.1）不接受任何变更：硬保护先于一切判定；真实误判当天进回归集；宁可漏报不可误报。
- **环境变更**（Python 版本、VM 环境、构建机迁移）：更新《[环境基线](环境基线.md)》的变更记录。
- **文档间冲突**：按"方案定稿 > 治理 > 敏捷指南 > 其他"优先级裁决，并在低优先级文档加注。

## 5. 决策记录（ADR-lite）

`docs/governance/decisions/` 存放增量决策，每条一个文件，命名 `DR-<序号>-<日期>-<标题>.md`，含四节：背景 / 决策 / 理由 / 影响面。既有决策（方案定稿的 D1~D4、Q1~Q7、P1~P10、X1~X6）以方案第十三节为准，不重复建档；此后新决策一律入册。已建档示例：

- DR-001（2026-10-24）：分支策略采用"短分支 + PR 合入 main"。
- DR-002（2026-10-24）：VM 磁盘定址 E 盘差分盘方案。**已被 DR-003 取代。**
- DR-003（2026-10-24）：VM 磁盘定址修订为 `H:\Virtual Machine`（H 盘 932G 余 117G；差分盘策略不变）。

## 6. 知识库治理

- **来源铁律**（方案 P10）：全部自行整理——本机 320 项长尾 + 公开软件名；**不复制 BCU 数据**；NOTICE 仅致谢思路来源。若未来实际复用 BCU 代码，须补版权头与声明，并新建 DR 决策。
- 每条知识库条目必须含**来源登记字段**（依据：本机实测 / 公开软件名 / 推断），生命周期标注（在用 / 已停止 / 未知）只允许登记有公开依据的结论。
- 正则族（`*-updater` / `*_pp` / 哈希 / GUID）与别名表属于知识库的一部分，同受来源铁律约束。
- 知识库修正（误判修复）当天同步回归集（底线二）。

## 7. 安全底线执行清单（任何 PR 不得违反）

| # | 底线 | 依据 | 检查方式 |
| --- | --- | --- | --- |
| S-1 | 硬保护规则在判定流水线最前短路，不可配置覆盖 | 方案 9.1 | pytest 100% 覆盖；代码评审 |
| U-2 | 程序自身仅在 `%LOCALAPPDATA%\DiskAudit\` 写入 | 方案八节 | Procmon 留档（M2 提权完成后做一次，M5 前复检） |
| U-4 | 系统交互白名单仅 A1~A3；`UninstallString` 永不调用 | 方案八节 | 代码评审 + grep 门禁可入 CI |
| DPAPI | `Roaming\Microsoft\Protect`、`Crypto` 永久"受保护" | 方案文末安全边界 | 硬保护测试用例锁定 |
| 提权 | 仅用户点击触发；提权后只读、不联网、不执行外部程序 | R9 | VM 验证 + VirusTotal 复测（U3） |
| 隐私 | 不收集、不上传、默认不联网 | 方案八节 | 代码评审；联网代码仅"检查更新"一处 |

## 8. 归档规范

- 上游资料（报告、POC、原型、外部数据）只进 `docs/upstream/`，登记其 README；工作区不散落副本。
- 含个人信息的数据（如桌面两份 TreeSize CSV 全量目录清单）**不进仓库**，按需在本地引用并在归档 README 标注原路径。
- 归档拷贝必须做完整性校验（文件数 + 总字节 + 关键文件 md5），结果记入归档 README。
