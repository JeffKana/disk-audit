# 任务执行

执行实例先读取[协作契约](../references/契约字典.md)，按项目风险和授权工作；标准/高风险任务使用[模板库](../references/模板库.md)的执行记录。仅写被分派的代码、测试和自己的执行制品，不写规划、验收、合入记录。

## 输入与输出

输入：已分派任务及标准版本、治理/安全约束、依赖和环境事实。输出：授权范围内的实现与测试、独立执行记录，以及获授权时的工作分支/PR。记录包括完成内容、实现决策及依据、未尽事项、自测证据和待验 head。

## 工作步骤

1. 核对任务责任实例、任务版本、依赖和授权；在自己的记录确认所读版本及时间。缺失、双重认领、同文件并行或标准冲突时停下报告 PM，不擅自取舍。
2. 阅读相关方案、项目规范和依赖代码；依赖未就绪则记录阻塞。按项目分支约定工作，栈式任务明确基线和先后顺序。
3. 根据任务风险和项目规范编写测试与实现；有判定或接口逻辑时优先用反例与可重复测试澄清行为。保持 I/O、环境与可测试逻辑的清晰边界，项目特有编码要求以项目规范为准。
4. 运行与变更及项目门禁匹配的测试/自检；记录命令、结果、限制及对应提交。无法执行的检查明确说明，不把本地结果当作远端 CI。
5. 补齐自己的执行记录四项与未尽事项；有授权时提交分支和 PR，标明标准逐项证据、栈关系及待验 head。交验收 PM 接收并确认版本。
6. 退回时按验收记录修复，在原工作分支或项目批准的替代路径更新记录和 head，再交 PM 重验。退回次数由验收 PM 记载，升级规则见契约。

需求或任务契约版本变化后，重读并重新确认；新的 head 不能沿用旧验收和检查。项目委派独立测试时交 `independent-test` 取证，不自行判定测试结果。CI 根因交 `ci-cd-ops`，通道/环境故障交 `ops-runbook`；不要在执行卡里自行放宽门禁或发明应急通道。
