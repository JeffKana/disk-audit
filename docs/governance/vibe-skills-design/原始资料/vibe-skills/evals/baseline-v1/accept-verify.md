# Skill: accept-verify · 交付验收（PM 角色）

**使用角色：PM**。本技能是《交付与验收流程》§3/§6 的可执行版。验收产物 = 一份可追溯的验收报告（先例结构：`0N_SprintN_验收报告.md`，随波次追加、Sprint 末终章）。

## 目标

对每个交付给出**可追溯、可复核**的三选一结论（通过 / 有条件通过 / 退回），并让验收输出反哺流程（待办状态、实测回填、回归集、决策记录、风险看板）。

## 触发场景

- 执行侧 PR/分支交付请求验收；里程碑闸门判定（如 M2 五闸）；条件项闭环复验；Sprint 评审。

## 输入

- PR/分支清单（含栈序关系）；任务卡验收标准；治理文档；CI 记录；执行记录。

## 输出

- 验收报告：逐卡结论总表 → 退回单 → 条件项与裁决 → PM 独立抽查 → 合入顺序 → 合入执行清单 → Sprint 数据与下阶段输入。
- 待办/卡状态回填；实测数据回填方案"实测"列；里程碑判定记录。

## 核心步骤（七步，有序执行，不得跳步）

1. **范围核对**：diff 只含任务卡范围（+ 必然联动的测试/文档）；越界改动一律退回（记卡待发），即使"改得更好"。
2. **规范符合性**：开发规范逐条——类型标注、判定纯函数、零依赖、异常口径、文案集中、注释只讲约束。
3. **测试审查**：验收标准每条有对应测试或可复现命令？判定逻辑有反例？真实误判/缺陷进回归集了？
4. **门禁核验**：PR 的 CI 全绿，**以远端为准**（本地仅辅助）。
5. **验收标准逐条判定**：按卡内标准打勾（通过/不通过+证据）；数据类标准核对数字与口径。
6. **只读/安全边界专项**：涉及文件系统/注册表/提权/网络的改动，对照治理安全底线清单逐条确认。
7. **结论三选一**：**通过** → 合入（CI 绿 + 栈序，按分权规则）；**有条件通过** → ≤3 条整改项，可合入，整改项限期下分支携带；**退回** → 写明现象/根因/修复要求/重验口径，重发执行，不合入（同一卡累计 2 次强制升级负责人）。

## 证据采集模式（按可用性择优，全部只读）

| 证据 | 手段 |
| --- | --- |
| 分支拓扑/栈关系 | 本地 git log/merge-base；远端 API |
| diff 与范围 | 本地 `git diff --stat A..B`（已 fetch 优先）；否则 API compare files |
| 测试与功能 | 本地裸跑全量测试 + 自检 + 端到端命令（**能用本地实证就不用转述**） |
| CI 结论 | 远端 CI/API（**远端为准，本地绿≠CI 绿**） |
| PR 描述/执行记录 | API pulls 或卡内执行记录区 |
| 数据类标准 | 本地复测并与执行记录数字交叉核对；内容终验用**树哈希/字节级比对**（tree sha 只由内容决定，与提交父级无关） |

## 验收后动作

合入（按分权）→ 更新待办/卡状态 → 联动检查（误判进回归集、实测回填方案、环境事实回填基线）→ 风险看板扫止损信号 → 全部卡关闭则触发下阶段规划。

## 里程碑闸门判定

- 闸门口径以方案第七节类文档为准，逐条列表：现状 → 目标 → 证据链接。
- **自指数据不作数**（先例：本机归属率 98.6% 因知识库源于本机被否，必须外部真值实测）。
- 判定后回填方案"实测"列与待办状态；解除或触发预设止损预案。

## 防死胡同机制（四条）

1. **返工上限**：同一卡退回 ≤2 次，第 3 次强制升级，选项只有换方案/拆卡/冻结。
2. **裁决时限与保守默认**：升级后 48 小时未裁决按保守默认推进（宁漏报不误报方向），事后补决策记录。
3. **数据裁决**：技术争议以测试/实测数据为准；执行侧按"冲突事实 + 数据 + ≥2 个带代价分析的选项"上报。
4. **预设 go/no-go**：闸口阈值规划期写死，到点判数据不无限延期；新阈值须先入决策记录。

## 可复用要点（跨项目保留的原则）

- **四类常见验收坑**（先例沉淀）：栈序包含（后合 PR 已含先合内容 → GitHub 自动标记 merged，属正常，落账即可）；texts/资源类文件多卡并行 → append-only + 逐行状态机解突 + **语义复核**（纯拼接会拆断函数）；"本地绿≠CI 绿"三类根因（真信号逃逸/locale/argv 泄漏）；交付前先合的 PR 内容已入 main → 后续 PR 解突必须基于**新鲜 main**（fetch 失败时禁止用过期基线解突）。
- **裁决留痕格式**：每条裁决 = 事实 + 数据 + 选项代价分析 + 结论 + （程序偏差时的）追认与修正一句话。
- **诚实度审查**：执行记录的未尽事项是否如实上报——三角色协作的信任基础，验收时明确表扬/点名。
- **条件项闭环跟踪**：有条件通过的整改项进入下阶段卡包，不落地不关闭。

## 项目参数定制位

- 里程碑闸门表内容；安全底线清单（治理 §7 类）的专项检查项。
- 数据类口径的对比基准与登记机制（先例：baseline.json 登记日期 + 高漂移目录标记）。
- 平台故障时的应急合入通道（先例：Git Data API 落分支 + CI 照常绿后 API merge + 树哈希终验——详见 ops-runbook）。

## 与其他 Skill 的边界

任务卡缺口 → plan-cards；执行侧冲突上报 → 转交负责人或按防死胡同裁决；平台故障 → ops-runbook；门禁设计演进 → ci-cd-ops。
