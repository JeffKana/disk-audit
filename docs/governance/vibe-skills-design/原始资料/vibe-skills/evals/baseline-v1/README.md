# vibe-skills · 面向多 Agent 协作开发的可复用 Skill 包

从 disk-audit 项目四轮 Sprint 的实际运行中沉淀的流程技能，面向"负责人 + 项目经理（验收 AI）+ 执行 Agent"三角色协作的 vibe coding 开发模式。**与具体项目解耦**：迁移新项目时复制进目标仓库 `.agents/skills/`，替换各技能的"项目参数定制位"即可。

## 一、流水线总览

```
00 项目立项与治理初始化（一次）
   └─ 产出：方案基线 + 敏捷三件套 + 治理文档 + CI/CD 规范 + 工程骨架
        │
        ▼
01 任务规划（每 Sprint 初，PM）──→ 02 执行推进（执行 Agent，逐任务卡）
   ▲                                        │
   │                                        ▼
03 需求验收（PM，逐 PR）──通过──→ 负责人/PM 合入（DR 分权）
   │                                        │
   ├──── 每轮回填：待办状态 / 实测数据 / 决策记录 / 回归集
   ▼
04 CI/CD 门禁管护（贯穿，PM+负责人）
05 平台与环境故障运行手册（随时，全体）
```

可选扩展：领域知识库治理（当项目核心资产含"数据/规则库"时自建，先例见 disk-audit 的 kb-curator）、测试实验室操作（当验收依赖专用环境/虚拟机时自建，先例 vm-ops）。

## 二、角色模型（三角色分权）

| 角色 | 承担者 | 职责 | 使用的技能 |
| --- | --- | --- | --- |
| 负责人 | 人 | 计划审批、资源、终审、（默认）merge 与发布、事故拍板 | 00 报批、01 报批、R-M 类验收卡 |
| 项目经理（PM） | AI | Sprint 计划与任务卡、治理维护、**验收判定**、里程碑把关、故障应对 | 01、03、04、05、00 |
| 执行 Agent | AI | 按任务卡开发、自测、提 PR | 02、05 |

**合入分权（先例 DR-006）**：执行侧 PR 由 PM 验收通过后合入（CI 绿 + 栈序）；PM 自己产出的 PR 交负责人把关。负责人如需越序合入，留"显式委托/自行把关"标注即可。

## 四、迁移指南（新项目三步）

1. **复制**：将本目录下六个技能目录（不含 README 与本层）复制到目标项目 `.agents/skills/`。
2. **定制项目参数定制位**：每个 SKILL.md 末尾的"项目参数定制位"节列出了必须替换项——仓库名/默认分支、语言栈与测试命令、写入合规目录、安全底线清单、角色映射（谁当负责人/PM/执行）、可注入依赖清单。
3. **跑一遍 00-bootstrap**：按该技能产出目标项目的治理文档链，之后 01→02→03 循环即成开发节奏。

## 六、可选技能的自建判据

- **领域数据治理技能**（先例 kb-curator）：当项目竞争力押在"数据/规则/知识库"上时必建——来源铁律、字段纪律、校验脚本、错误回灌流程四件套。
- **测试实验室操作技能**（先例 vm-ops）：当验收依赖虚拟机/专用硬件/长驻环境时必建——机队清单、启停纪律、guest 通道坑、防睡/探活、排障实录回填机制。
- 共同要求：环境或数据事实变更**必须回填技能与基线文档**，让"排障一次、全员复用"。

## 七、成熟度声明

本包为单项目（disk-audit，四轮 Sprint、40+ PR、三次里程碑闸门）实证后的首次泛化。两类内容可信度最高：验收七步/DoR/红线（反复运行 40+ 次）、故障运行手册（真实事故驱动）；两类内容需在目标项目校准：门禁分阶段的阶段划分节奏、可选技能判据。迁移后首个 Sprint 建议按 00-bootstrap 的"试运行 Sprint"小步验证并回填本包。
