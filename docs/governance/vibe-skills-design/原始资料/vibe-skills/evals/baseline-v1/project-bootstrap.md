# Skill: project-bootstrap · 项目立项与治理初始化

## 目标

把"一份立项材料"变成"一套可立即开跑的治理化工程"：范围基线冻结、流程规范成文、门禁就位、首个 Sprint 可分发。**核心判断：先治理后编码**——第一行正式代码应落在有门禁、有测试、有追溯的骨架上。

## 角色与触发场景

- **角色**：PM 主导产出，负责人审批（方案基线与安全底线必须负责人确认）。
- **触发**：①新项目立项；②已有可行性报告/方案文档待进入开发；③项目进行中但治理缺失（无基线/无门禁/无验收标准）需要补建。

## 输入

- 立项材料：需求/可行性文档、痛点描述、既有原型或调研。
- 环境事实：语言栈、平台、可用工具链、既有仓库状态。

## 输出

1. **方案基线确认结论**（分析结论 + 缺口清单 + 不阻塞项）。
2. **敏捷三件套**：开发指南（节奏/角色/DoD/变更管理）、产品待办列表（可追溯编号）、首个 Sprint 计划。
3. **治理文档链**：项目治理（分支/变更/发布/知识库/安全底线）、开发规范、环境基线、决策记录目录（ADR-lite，编号从 DR-001 起）。
4. **CI/CD 规范**（与 04-ci-cd-ops 对接）。
5. **工程骨架**：包结构 + 测试 + 构建配置 + LICENSE + CI 初版。
6. 首个 Sprint 任务卡包（交 01-plan-cards 或由本技能内联产出）。

## 核心步骤

1. **基线确认**（只读分析）：通读立项材料 → 结论（定位是否闭环/难点是否落入硬约束/数字是否可信）→ 问题清单（均标"不阻塞"）→ 与负责人确认。**产出必须回写立项材料的缺口，而不是默默补齐。**
2. **范围冻结**：In/Out 双清单 + EARS 或等价可验收条目 + 里程碑表（每阶段带验收口径与止损信号）。里程碑的 go/no-go 阈值**此刻写死**。
3. **治理落档**：按 `references/治理文档骨架.md` 产出治理文档链；**安全底线单列成表**（任何 PR 不得违反，逐条标检查方式）；决策记录从 DR-001 开始（重大分叉皆入册）。
4. **角色与分权设立**：三角色表（负责人/PM/执行 Agent）+ 合入分权规则（先例 DR-006）+ AI 协作守则（AI 产出必经人审+CI、AI 不越权 push/发布）。
5. **CI/CD 规范**：按 04-ci-cd-ops 定阶段门禁与触发矩阵（首 Sprint 只上阶段 A，勿提前实现）。
6. **工程骨架**：包结构 + 首个可测模块（如安全底线类模块，先例：硬保护规则模块 + 27 用例）+ 测试跑通 + LICENSE + .gitignore（含会话产物）。
7. **首个 Sprint 计划**：目标一句话 + 可打勾验收清单 + 任务卡（DoR 齐备）+ 负责人三件事清单（建远端/环境确认/首次推送）。

## 可复用要点

- **定稿标准**：方案文档"不含待定项"才算基线——歧义条目（命名/许可/口径/版本）逐条关闭并留变更记录编号。
- **实测先行**：性能/包体等数字必须"目标+实测"成对出现且标注验证阶段，禁止把原型数据当承诺。
- **先例回灌**：立项材料引用的原型代码/调研结论/事故教训，逐一映射为骨架模块、测试用例或卡内硬约束（W0 POC 教训 → CI 门禁的模式）。
- **骨架自证**：首模块必须"代码+测试+自检命令"三件套，作为 CI 阶段 A 的第一个绿灯。
- **风险登记册**：每条风险带"止损信号→动作"，评审时过止损线而非泛泛过风险。

## 项目参数定制位

- 语言栈与版本、构建/测试命令（骨架与 CI 各一处）。
- 安全底线清单内容（DPAPI/只读边界等 → 换成目标项目的不可逆风险清单）。
- 里程碑划分与周期（本先例：12 周五里程碑）。
- 数据目录/写入合规位（U-2 类约束）。
- 角色映射与沟通渠道。

## 与其他 Skill 的边界

产出后交棒：01-plan-cards 接管节奏、02-task-exec 接管执行、03-accept-verify 接管验收、04-ci-cd-ops 接管门禁演进。本技能不再介入日常迭代；治理文档的修订走变更记录，不回本技能。
