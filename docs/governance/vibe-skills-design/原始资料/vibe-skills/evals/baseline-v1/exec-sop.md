# Skill: exec-sop · 任务卡执行（执行 Agent 角色）

**使用角色：执行 Agent**。交接契约：《交付与验收流程》§2；对 PM 的任务卡负责，对验收标准无修改权。

## 目标

把一张任务卡变成一个"范围干净、测试齐备、自测跑绿、执行记录完整"的 PR——让 PM 的验收只做判定，不做考古。

## 触发场景

- 领取/开始一张任务卡；修复退回 PR 或 CI 红灯；任务卡内容变更后的重执行。

## 输入

- 任务卡（含验收标准与依赖标注）；治理文档链（项目治理/开发规范/环境基线）；依赖模块代码。

## 输出

- 一个分支 + 一个 PR：代码/测试/文档变更 + 执行记录四项回填（做了什么 / 实现决策及依据 / 未尽事项 / 自测输出摘要）+ PR 描述（验收标准逐条 + 自测结果 + 栈序说明）。

## 核心步骤（九步，有序执行）

1. **先读后做**：任务卡 → 方案对应节 → 开发规范/治理条款 → 依赖模块代码。**任何一项与卡面冲突，停下来上报冲突，不自行取舍**（先例：性能预算与实测冲突 → 四选项数据上报待裁，被裁决采纳并表扬）。
2. **确认依赖**：依赖未就绪 → 执行记录标"阻塞：依赖 xxx"并回报；不顺手先做依赖外的事。
3. **建分支**：`feature/<待办ID>-<摘要>`；栈式依赖在 PR 描述写明"基于 X 分支切出"。
4. **测试先行**（判定/接口类逻辑）：先写用例（含反例）跑红 → 实现跑绿。
5. **编码**（开发规范要点）：签名类型标注；**核心逻辑纯函数化 + 依赖可注入**（I/O 与判定分离，I/O 只在采集/装配层）；异常按卡面口径（先例 X-1：跳过+计数+继续）；对外文案集中资源处不硬编码；注释只讲约束不讲改动史。
6. **自测**：本地全量测试 + 自检命令 + 端到端命令，输出摘要进执行记录。**注意"本地绿≠CI 绿"**——本地只是开发自测，远端 CI 才是门禁（见可复用要点 3）。
7. **回填执行记录**：四项齐全；未尽事项**如实记录**（先例：性能未达、口径差异、CI 未复验全部如实上报——诚实度是三角色协作的信任基础）。
8. **提 PR**：Conventional Commits + 中文描述；描述 = 验收标准逐条 + 自测结果 + "AI 辅助生成，待验收" + 栈序/并行关系 + 解突预告（若与他卡同文件）。
9. **退回处理**：按退回单逐条修复 → 推回**同分支** → CI 绿 → 交 PM 复验。退回计数（同一卡累计 2 次强制升级负责人）。

## 九条红线（每卡通用）

1. 不 merge、不 push main（main 受保护；工作分支 push 自办）。
2. 不修改任务卡验收标准；标准不可达时**上报冲突**而非私下放宽。
3. 只写项目合规目录；对被操作对象零写入（按项目安全底线）。
4. 发现新问题记"未尽事项"，不顺手修（另立任务）。
5. 越界改动即使"更好"也不做。
6. 测试三禁：禁抛真实 KeyboardInterupt 类 BaseException、断言禁依赖系统 locale、CLI/`main()` 调用显式传参。
7. 命令拆小执行；对外文案集中资源处。
8. 不修改 CI/workflow 文件（除非卡面显式授权并留痕）。
9. git push / merge / 发布的权限边界按项目治理（先例：工作分支 push 自办，main 永远走 PR）。

## 可复用要点（跨项目保留的原则）

- **纯函数 + 注入模式**：判定/计算逻辑 = 纯函数（时间、随机、环境变量、I/O 全部可注入），测试无 Tk/无网络/无 locale 依赖。
- **结构性安全防线**（agent 生成代码的高危调用）：危险系统调用单点化（全仓库唯一出口 + AST 断言调用点唯一）、一次性资源原子认领即焚、UI 无自动重试——先例：runas 防重生四道防线。
- **环境差异三类假绿及对策**（真实事故沉淀）：真信号逃逸（测试中抛真 KI/BaseException → 改自定义异常替身）、locale 依赖（mbcs/编码断言 → 编码表可注入）、argv/环境泄漏（main/CLI 调用显式传参）。
- **并行 append-only 纪律**：多卡改同一资源文件一律文末追加区块；改既有测试语义与新增测试**不得同文件并行**；解突用逐行状态机 + 语义复核（纯拼接会拆断函数）。
- **回归集回灌**：真实误判/缺陷当天进回归集，用例含根因与禁词断言。
- **数据裁决的上报格式**：冲突事实 + 探针/A-B 数据 + ≥2 个带代价分析的选项，交 PM/负责人裁。

## 项目参数定制位

- 测试命令与自检命令（完整解释器路径）；合规写入目录。
- 分支命名与 PR 描述模板字段。
- 项目安全底线清单（治理 §7 类）。
- 构建环境事实（解释器路径/编码默认值/平台差异——登记在环境基线并指向它）。

## 与其他 Skill 的边界

任务卡从 plan-cards 来；验收交 accept-verify；CI 红灯的根因分类查 ci-cd-ops；平台故障（推不上/事件管道不响应）查 ops-runbook——**不要在执行卡里自行发明应急通道**。
