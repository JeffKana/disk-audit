# Skill: ci-cd-ops · CI/CD 门禁管护（PM + 负责人角色）

## 目标

让"合入"永远由机器门禁把关而非人的自觉：分阶段建设流水线、红灯有分类处置、CD 有人工闸门、平台故障有合规降级通道。

## 触发场景

- 项目初始化制定 CI/CD 规范（与 00-bootstrap 对接）；新门禁接入或阶段升级；CI 红灯诊断；分支保护配置/变更；发布流程建设；讨论应急合入。

## 输入

- 仓库现状（workflow 文件、保护规则、CI 运行记录）；语言栈与构建方式；里程碑计划。

## 输出

- CI/CD 规范文档（分阶段门禁全景 + 触发矩阵 + 处置表）；workflow 文件变更（走 PR）；红灯诊断结论；分支保护配置清单。

## 核心步骤

### 1. 门禁分阶段设计（与里程碑对齐，不提前实现）

| 阶段 | 内容（先例，按项目替换） | 接入时点 |
| --- | --- | --- |
| A 基础门禁 | 环境断言（先例 tkinter：缺失只在运行时暴露）→ 全量测试 → 内置自检 | 首个 Sprint |
| B 零依赖与构建 | import 白名单扫描 → 打包 → 产物内断言 + 产物自检 | 引擎成型后 |
| C 里程碑验收 | 回归集全量 + 性能基准（阈值告警不阻断） | 里程碑前，手动触发 |
| D 发布 | 双形态产物 → 校验和 → **Release 草稿** → 人工闸门后发布 | 发布期，tag 触发 |

### 2. 触发与合入矩阵

- PR（→main）：合入前置门禁；push main：合入后复核；tag：发布流水线；手动：里程碑验收。
- **main 保护三件**：PR-only、必填状态检查（CI 名单——**新增门禁 job 必须同步登记必填列表**，否则不设防）、禁 force push；`enforce_admins` 与 `delete_branch_on_merge` 按需开启并写入规范。
- 每条门禁的失败处置写死（先例：tkinter 断言失败→查 runner 环境，不得跳过；红灯禁止删用例换绿）。

### 3. 红灯诊断分类（先验分类，加速定位）

1. **环境差异类**（本地绿 CI 红）：locale/编码（stdout 默认代码页 → `PYTHONUTF8=1` + 脚本内 reconfigure 双保险）、真信号逃逸（测试抛真 BaseException → 改异常替身）、平台路径/凭据差异。
2. **测试质量类**：环境碰巧一致的假绿（断言未锚定身份 → 显式锚定）；argv/状态泄漏（→ 显式传参）。
3. **真缺陷类**：进入退回流程，当天修复优先。
4. **流程类**：门禁自身缺陷（如未登记必填检查）→ 修 workflow 走 PR。

### 4. CD 原则（不可协商）

1. **不自动发布**：Release 永远草稿态等人工确认（与产品"不自动更新"哲学同源）。
2. **产物不进 git**：仅存 artifact/Release 附件；`.gitignore` 永久排除。
3. **可追溯**：Release 对应 tag + commit + CI 链接；校验和由流水线生成不手写。
4. **发布前置条件**：里程碑验收全过 + 回归集 100% + 产物三件套 + 安全留档齐备（逐项 checklist）。

### 5. 应急合入的合规边界（平台故障期，详见 05-ops-runbook）

- 允许：经 api.github.com 的 Git Data API 落分支（blobs→tree→commit→ref）→ **CI 照常触发并全绿** → API merge；全程留痕于验收报告。
- 禁止：绕过 CI 直接改 main（分支保护 enforce_admins 也挡）；用未跑 CI 的 commit 走 admin 强合。
- 合入后终验不依赖下载：**树哈希比对**（tree sha 只由内容决定）证明服务端 main 与本地已测状态逐字节一致。

## 可复用要点

- **门禁先于功能**：第一行正式代码前先有阶段 A（先例教训：环境缺陷只在运行时暴露，构建日志不报错）。
- **门禁失败不可绕过只能修复**；"本地绿≠CI 绿"是常态而非异常——CI 拦截即门禁在产生价值（先例：三连拦截环境差异假绿，报告明确表扬）。
- **CI 配置文件本身走 PR**；红灯时先查代码不改 workflow 换绿。
- **指标留存**：CI 时长/红灯次数/失败步骤分布，随里程碑验收回填。
- **零机密设计**：不引入 token/签名密钥（GITHUB_TOKEN 足够）；未来需要先建决策记录。

## 项目参数定制位

- 各阶段门禁的具体命令（环境断言/测试/自检/构建工具）。
- 产物形态与发布目标；必填检查名列表。
- 机密/签名策略；tag 命名与版本号来源。

## 与其他 Skill 的边界

门禁失败根因属执行侧 → 退回流程（accept-verify/交付与验收流程）；平台断网/事件管道故障 → ops-runbook；门禁阶段升级的时机 → 随里程碑规划（plan-cards）。
