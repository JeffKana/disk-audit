# Skill: plan-cards · 任务规划与任务卡制作（PM 角色）

本技能是《交付与验收流程》§6 的可执行版。**使用角色：PM**；产出经负责人报批后生效。

## 目标

每个 Sprint 以"一张可分发的任务卡包"开局：目标一句话、依赖拓扑清晰、每卡验收标准可独立判定、DoR 自查通过。

## 触发场景

- Sprint 计划会（周期初）；里程碑验收后的下阶段规划；范围调整/砍卡后的重排；临时插卡。

## 输入

- 上一 Sprint 验收报告（完成率/退回/缺陷/CI 记录）；产品待办列表（剩余条目+状态）；里程碑验收口径（方案第七节类文档）；风险登记册（止损信号扫描）；上轮实际产能。

## 输出

- 《N_SprintN_计划与任务卡.md》：目标一句话 + 打勾验收清单 + 分波次任务卡（每卡 DoR 齐备）+ 里程碑闸门表（如适用）。
- 状态回填：待办列表对应行、Sprint 总览行、上轮报告"下阶段输入"勾销。

## 核心步骤（五步，有序执行）

1. **收数**：完成率（有条件通过计 0.5）、退回次数与原因分布、缺陷与回归集增量、CI 红灯记录（红灯类型分类：环境差异/真缺陷/流程缺陷）、风险止损信号扫描。**数据全部给出处。**
2. **对表**：对照当前里程碑验收口径与待办剩余条目找差距；闸门阈值必须已预先写死，到点按数据判，**不做无限延期**。
3. **排程**：优先级 = 里程碑闸门缺口 > 依赖拓扑 > 上轮实际产能。连续两周完成率 <70% → 砍范围不加班。并行卡标"无依赖可同时领取"；栈式卡标"基于 X 分支切出"；**同文件高风险并行要显式预警**（多卡改同一文件时注明合入顺序与解突方式）。
4. **成卡**（DoR 自查通过才能发）：
   - 卡字段：待办 ID / 目标一句话 / 输入指针（方案节号+DR+代码路径，精确到文件）/ 实现约束（历史教训写成硬约束）/ 验收标准（①②③，可执行命令或可测条件，数据类写明口径）/ 依赖（并行或栈式）/ 执行记录四项留空区。
   - 自查四问：字段齐吗？验收标准可独立判定吗？依赖就绪或已标注吗？单卡 ≤2 天吗（超出先拆）？
   - 文件头放**通用红线**段（不随卡重复）：不 merge/push main、不改验收标准、只写合规目录、新问题记未尽事项不顺手修、命令环境注意。
5. **报批**：目标 + 打勾清单 + 卡包交负责人确认；负责人改哪条，PM 重排依赖后再生效。

## 可复用要点（跨项目保留的原则）

- **验收标准可执行化**："贴实测数字/截图/退出码"，禁止"看起来对"；数据类标准写明口径与对比基准。
- **闸门口径预先写死**：里程碑 go/no-go 与止损预案在规划期定死，到点判数据（先例：归属率 <70% 即收缩范围）。
- **历史教训 → 卡内硬约束**：每个已发生的事故/退回都应出现在后续卡面的"实现约束"里（先例：真 KI 逃逸 → "测试禁抛真 KI"；locale 假绿 → "断言禁依赖系统 locale"）。
- **栈式依赖显式化**：分支包含关系写进卡与 PR 描述，防乱序合入带进未验收内容。
- **产能对赌**：排程用上轮实际产能而非理想产能；完成率连续不达标先砍范围。
- **同文件并行预警**：多 Agent 并行改同一文件（如文案资源）时，卡面约定 append-only 与合入顺序，并预设解突责任人。

## 项目参数定制位

- Sprint 周期与里程碑编号体系；待办列表/验收报告文件命名（先例 `0N_SprintN_验收报告.md`）。
- 卡号体系（先例 T<N>-<NN>）；分支命名规范；规模估算单位（S/M/L ≈ 0.5/1~2/3~5 天）。
- 里程碑验收口径的文档位置（先例：方案第七节）。

## 与其他 Skill 的边界

验收与数字回填 → accept-verify；卡内技术口径只指 DR/方案节不复制正文；执行 → exec-sop；门禁与平台故障 → ci-cd-ops / ops-runbook。
