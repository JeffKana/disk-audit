# 交付验收

验收 PM 先读取[协作契约](../references/契约字典.md)；标准/高风险任务使用[模板库](../references/模板库.md)的验收记录。读取任务版本、执行证据、PR head 和 CI；标准/高风险且项目委派了独立测试时，把独立测试报告作为验收输入。只写本人持有的验收制品。发现上游版本变化时重新确认受影响证据；独立测试报告的 head 与待验 head 不一致时，同样先重新确认受影响证据再下结论。

## 输入与输出

输入：任务与验收标准、执行记录、变更 diff、当前 head 的 CI、项目规范和安全底线；标准/高风险且已委派独立测试时，还包括 independent-test 产出的独立测试报告。输出：逐项证据、通过/有条件通过/退回、条件项或退回单，以及对规划 PM 的状态更新建议。验收判定不自动赋予合入权限。

## 七步验收

1. **范围**：对照任务与 diff；超出约定范围的部分先裁决或退回。
2. **规范**：对照项目实际开发规范、依赖与约束，不把其他项目示例当本项目硬要求。
3. **测试**：标准/高风险任务引用 independent-test 的独立测试报告作为测试证据输入，按契约字典单写者规则只读核对、不代写其内容；每条标准有可复现证据；检查关键反例、缺陷回归和未执行项目。
4. **门禁**：核验当前 PR head 的远端必需检查；本地绿不能代替远端，未满足不得合入。无 PR 时记录适用性与等效验证。
5. **验收标准**：逐条给结论、数据口径及来源；必要时独立复测，避免只转述执行记录。
6. **安全**：涉及文件系统、注册表、提权、网络、数据或发布时，逐项核对项目安全底线；不适用须说明。
7. **结论**：按契约给出通过、有条件通过或退回；条件项记录责任人、期限、跟踪位置及证据；退回单写现象、根因或待查项、修复要求和重验口径。

写入执行记录版本、接收实例/时间、实际验收的 head 与证据；验收记录按契约字典引用独立测试报告的版本与位置，不代写、不并入验收文件。第 2 次退回后按契约立即升级。交合入责任人确认验收版本与 head；合入记录由合入者独立持有，PM 只引用。通知规划 PM 更新状态与后续项，不直接改其文件。

## 里程碑与回填

对照预先确定的口径列出「现状 → 目标 → 证据」，区分真实外部基准和自指数据；按项目权限裁定 go/no-go、回填由自己持有的实测制品。回归测试由指定文件写入者落实，环境事实交基线持有人。CI/平台故障分别交 `ci-cd-ops`/`ops-runbook`，不能用应急通道免除验收。
