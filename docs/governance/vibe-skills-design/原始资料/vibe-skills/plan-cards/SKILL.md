# Sprint 规划与任务卡

PM 读取[协作契约](../references/契约字典.md)确定 DoR、风险强度、分派、状态和写入者；需要制卡时使用[模板库](../references/模板库.md)的任务模板。规划 PM 是所负责 `task.md` 的唯一写入实例，首批和后续任务均由本技能发卡。

## 输入与输出

输入：范围与里程碑口径、待办及依赖、风险、实际产能，以及已有验收或故障证据。输出：经项目要求批准的 Sprint 目标、依赖顺序、可分派任务与风险级别；由规划 PM 更新其持有的待办、风险、分派及任务主状态。引用验收结论，不修改验收记录。

## 工作步骤

1. 汇总已完成工作、退回与缺陷、CI 红灯和风险证据；缺数据时明确标注，不编造产能或完成率。对照预定里程碑阈值和剩余待办调整范围。
2. 按价值、依赖与实际产能排序；单卡过大则拆分。标注可并行和栈式依赖。同文件高风险改动优先串行或拆文件，确认集成顺序及责任人。
3. 按契约 DoR 写目标、输入、范围、约束、可执行验收标准和依赖；按风险选择轻量、标准或高风险载体。任务只引用权威规则，不复制可能漂移的标准。
4. 逐卡指定一个执行实例和版本，记录分派时间与责任；请求执行者确认。多个实例请求同一卡或同一文件时暂停分派并协调，不能假定文档提供原子锁。预计时限到期只触发检查，不自动重派。
5. 按项目需要交负责人审批，收到调整后重新检查依赖。验收 PM 的结论和状态建议到达后由规划 PM 更新任务及待办；有条件通过的事项记录责任人、期限、跟踪位置和关闭证据。

## 交接检查

DoR 完整，任务和标准版本可追踪，执行实例、验收者及适用时的合入责任人明确；下游 ACK 包含其所读版本。范围或验收标准变更后更新任务契约版本、通知下游重新确认；仅更新主状态不改变契约版本。
