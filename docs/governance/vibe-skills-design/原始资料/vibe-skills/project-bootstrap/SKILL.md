# 项目立项与治理初始化

按需读取[协作契约](../references/契约字典.md)；生成治理文档时读取[模板库](../references/模板库.md)的治理骨架与 DR 模板。PM 主导，负责人按项目权限确认范围、安全底线和重大决策。用户已有选择和权限边界优先，不因套用模板扩张范围。

## 输入与输出

输入：立项材料、需求与原型、仓库和环境事实、现有项目约束。输出：带缺口的基线结论、范围与里程碑口径、治理文档链、可测工程骨架及 CI 初版的提案/已授权变更、首个 Sprint 的规划输入。分派任务卡由 `plan-cards` 产出。

## 工作步骤

1. 核对方案的目标、关键约束、数据依据和缺口；把待定项写回材料或决策记录，区分阻塞与非阻塞项，不把假设当既定事实。负责人确认范围基线及安全底线。
2. 写清 In/Out、可验收目标、里程碑和预设 go/no-go/止损口径；目标值与实测值分开，记录验证阶段。重大分叉按项目权限写 DR。
3. 按项目实际需要建立治理、开发规范、环境基线、待办与决策记录；逐项明确安全底线、验证方法和单一持有人。确认角色映射、授权、任务风险分级和合入分权。
4. 与 `ci-cd-ops` 对接最小可用门禁及触发矩阵；在授权范围内建立可测试骨架，验证基本测试与自检。更高阶段门禁根据项目里程碑引入，不硬套先例节奏。
5. 形成首 Sprint 目标、已知依赖与待办，将版本化输入交 `plan-cards` 并获得接收确认；明确缺失项、项目定制参数及后续治理持有人。

## 完成检查

范围、安全、角色/授权、可运行的基本验证和待办输入有证据；不能完成时如实列出阻塞项。治理资产先行的程度应与项目实际风险匹配，不得擅自重建已有仓库或代用户批准外部动作。
