# vibe-skills · 多角色协作开发

七个流程技能支持负责人、项目经理（PM）和执行 Agent 协作；角色可由人或 Agent 承担，具体权限以用户授权和目标项目治理为准。包由协调者或客户端选择技能，Markdown 约定本身不提供锁、自动调度或并发仲裁。

## 选择技能

| 技能 | 使用时机 | 交接或边界 |
| --- | --- | --- |
| [project-bootstrap](project-bootstrap/SKILL.md) | 新项目或治理缺失，需要建立开发基线 | 交规划输入，不代替规划发卡 |
| [plan-cards](plan-cards/SKILL.md) | 排 Sprint、拆卡、分配或重排任务 | 持有任务定义、分派和主状态 |
| [exec-sop](exec-sop/SKILL.md) | 执行已分派任务、修复退回项 | 提交执行证据，不更改验收标准 |
| [accept-verify](accept-verify/SKILL.md) | 判定任务、PR 或里程碑是否达标 | PM 持有验收结论；合入权另按分权确定 |
| [independent-test](independent-test/SKILL.md) | 项目委派独立测试时对被测 head 取证并产出测试证据 | 产出 test-report.md；不判定验收、不触发合入 |
| [ci-cd-ops](ci-cd-ops/SKILL.md) | 设计门禁、诊断 CI 红灯或发布流程 | 管门禁设计；平台通道故障交运行手册 |
| [ops-runbook](ops-runbook/SKILL.md) | Git、CI 事件通道或本地环境故障 | 故障取证和恢复；不降低门禁 |

主链是 `project-bootstrap → plan-cards → exec-sop → accept-verify`；验收后的下一 Sprint 回到 `plan-cards`，是新的迭代。独立测试是待验收阶段的旁路证据环节：项目委派时由 `independent-test` 对被测 head 取证，测试结论为失败或阻塞时经验收退回形成回环，不在主链上。CI/CD 和故障处理按需介入；技能之间的双向链接仅作导航，不代表执行依赖成环。

[契约字典](references/契约字典.md) 是跨技能规则与制品所有权的唯一维护源；各技能负责自己的操作步骤。[模板库](references/模板库.md) 提供任务与交接制品骨架。项目的明确授权、安全边界和既有约定优先；本包不自动授权创建 PR、合入、修改远端或发布。

## 迁移与部署

1. 保留本目录作为维护源。确认项目角色、默认分支、保护规则、安全底线、测试命令与批准权限；没有这些条件时先记录缺口。
2. 建议从包根运行 `python scripts/build_distribution.py <新建的空输出目录>`。脚本将生成七个独立技能目录，按各技能正文的实际引用，把所需共享资料从单一维护源复制到该技能的 `references/` 并改写链接；不会修改源文件或覆盖已有目录。每个技能都必须引用契约，其余资料按需要引用，未被引用的资料不会进入该技能目录（按需加载）。发布根另含一份与维护源逐字节一致的 CHANGELOG.md；安装内容为七个技能目录及根级 CHANGELOG.md，后者位于安装根，不进入单个技能目录。重新发布请生成到新的空目录，避免把生成副本当作维护源。
3. 如果客户端明确允许读取技能目录外的兄弟文件，也可将整个包的七个技能目录、`references/` 与包根 `CHANGELOG.md` 一起复制到同一父目录，保持 `../references/` 路径；不要只复制七个技能。是否允许跨目录读取由具体客户端决定。
4. 按客户端实际使用方式打开技能并读取其契约及所需模板，做一次真实加载验证；加载实例回报其实际读取的技能路径与契约字典版本（共享规则文件版本，取自七个技能目录共同父目录即包根的 CHANGELOG.md；对应契约字典的交接字段）。失败时使用第 2 步的独立发布目录。静态路径存在不代表客户端一定加载成功。
5. 使用编排平台或客户端自动化进行派发时，部署前先做接入验证：确认版本读取、技能启动、输入送达、完成回执、超时与停止后恢复各环节行为符合项目预期。编排能力由平台提供，本包只提供状态与证据契约；派发说明须显式声明本次使用的技能与契约版本，角色到实例的映射按契约字典由规划 PM 单点指定，不由平台自动指派。接入验证记录须包含实际读取的技能路径与契约字典版本；同名技能出现多来源注册时，按确切 ID（exact ID）选择，不得以名称近似匹配。接入验证属于部署前置而非验收，回执成功不推进任务状态。所选入口不可用时，报告原始错误并停止，不切换替代入口掩盖故障。
6. 根据项目风险选择契约中的执行强度。对新项目使用 `project-bootstrap` 建立基线，再由 `plan-cards` 负责首批任务卡；首个 Sprint 小范围试运行并复盘。

## 检查和评估

- `python scripts/check.py package`：离线检查本包的技能入口和本地 Markdown 链接。
- `python scripts/check.py project <任务目录的父目录>`：检查采用模板中机器可读头部的标准/高风险任务制品，且仅适用于制品以任务目录文件为载体的项目。若项目治理文档选用 PR 评论、CI 制品等外部载体，则不使用本模式做一致性判定，改由人工核对；轻量模式、真实权限与并发竞争同样需人工核对。检查范围和限制见脚本帮助及模板库「制品存放与入库」。检查器输出不构成验收结论或合入授权（见契约字典）。
- 包版本与契约字典版本以包根 `CHANGELOG.md` 为单一事实源；包根为维护源包根、发布副本根或安装根，即七个技能目录的共同父目录，该文件不随单个技能目录复制。`契约字典.md` 首部的「契约字典版本」锚点是各副本的只读标识，安装副本随包同步、不独立改版；`check.py package` 核对锚点存在、格式与同根各副本一致，并核对根级 CHANGELOG.md 首条以 `## X.Y.Z` 起始的合法版本条目与锚点一致。
- [效果评测](evals/效果评测.md) 保存代表性任务、评分方法和原版快照说明。案例集为 E1–E10，A/B/C 对照的运行前置条件清单见该文件。结构检查不等于真实 Agent 效果测试。

## 成熟度与定制

原版来自 disk-audit 的四轮 Sprint、40+ PR 和三次里程碑闸门；这是来源项目的经验陈述，并非本次独立复核的实验数据。验收七步、DoR、执行边界和故障事实回填保留为核心经验；门禁分阶段节奏、项目特有安全底线、可选技能判据仍需目标项目校准。

需要领域数据/规则库治理或专用测试环境时，可以另建技能，明确其输入、输出和写入者；本包的 `independent-test` 即按此方式新增的旁路证据技能。Windows/MSYS、GitHub 和 Python 的排障经验在运行手册中仅是示例，迁移时按实际平台验证。
