# DR-001 · 分支策略采用"短分支 + PR 合入 main"

- 日期：2026-10-24
- 状态：已采纳

## 背景

单人 + AI 辅助开发，需要在"节奏最快"与"防止未经门禁的代码（尤其 AI 生成代码）直接进主干"之间取舍（方案 R6：单人 + AI 导致代码腐化）。

## 决策

所有变更走短分支 + PR 合入受保护的 main：CI 必绿才可合并、禁止 force push、负责人自审合并。分支命名与 PR 要求见《项目治理》§2。

## 理由

push 直推虽最快，但坏提交会短暂停留在 main；PR 制把 CI 四段门禁从"事后发现"变为"合入前置"，对 AI 产出代码多一道强制闸。单人自审成本可接受（每 PR ≤10 分钟）。

## 影响面

- 仓库设置：main 分支保护规则（负责人在 GitHub 配置一次）。
- 日常流程：每故事一分支，1~3 天合入。
- CI：现有 workflow 无需改动（push + PR 双触发）。
