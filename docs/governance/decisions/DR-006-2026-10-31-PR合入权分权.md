# DR-006 · PR 合入权分权：执行侧 PR 由 PM 验收后合入，PM 产出 PR 由负责人把关

- 日期：2026-10-31（深夜，Sprint 2 收尾期）
- 状态：已采纳（负责人指示）

## 背景

Sprint 1~2 的实际运行中，每次验收通过后仍需负责人手工 merge，多一轮交接且无额外把关价值——专业判断发生在验收环节（七步 SOP 的结论），合入只是该结论的执行动作。负责人 2026-10-31 指示：把 PR 合入的把关职责移交 PM 验收环节；同时 PM 自己产出的 PR（验收报告、治理文档、DR）仍由负责人把关，避免"自己验收自己合入"的闭环。

## 决策

1. **执行侧 PR**（执行 Agent 的工作分支：feature/fix/chore/docs）：执行 Agent push + 建 PR（CI 绿）→ PM 按《交付与验收流程》§3 验收 → **PM 决定并执行合入**：通过/有条件通过即合入（尊重栈序），退回不合。GitHub 侧 main 保护规则不变（PR-only + 必填 check `windows` + enforce_admins）。
2. **PM 产出 PR**（PM 撰写的验收报告、治理文档、决策记录等）：PM push + 建 PR → **负责人把关合入**；负责人可显式委托 PM 代为操作（逐 PR 或整体授权，委托在对话/报告中留痕）。
3. **负责人保留**：范围/排期/风险终审、发布把关、本 DR 的撤销权；对 PM 的合入决定有否决与回滚权（git revert 走新 PR）。
4. PM 的合入操作经负责人已授权的 gh 凭据执行；merge 记录在 PR 页可见，验收报告的"合入执行记录"节登记。

## 理由

- 验收结论与合入动作合一，消除"验收完等人合"的空转（Sprint 1~2 每轮 1~3 天等待）。
- 把关并未消失而是前移：CI 门禁 + 七步 SOP 是实质闸门，merge 是结论的执行；负责人从"每次点按钮"转为"把住 PM 产出与终审"两点。
- PM 产出 PR 保留负责人把关，隔离"运动员兼裁判"风险。

## 影响面

- 《项目治理》§2、《交付与验收流程》§0/§3/§4、《CI-CD 规范》§2、《开发规范》§6、《敏捷开发指南》§1 同步修订。
- 技能同步：exec-sop（红线 1/9、第 8 步）、accept-verify（merge 权、第 7 步结论、报告结构）。
- 《开发规范》§6 遗留的"git push 归负责人"漂移一并修正（push 自办 + merge 分权）。
