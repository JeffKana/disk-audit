# 环境修复记录 · AI 会话原生 exe 挂起（2026-10-24）

本文是《[环境基线](环境基线.md)》§4"AI 会话命令通道"结论的**修复记录**。《环境基线》的正式变更登记由验收环节依据本文执行（负责人 2026-10-24 指定），本文为登记输入，不直接改动《环境基线》。

## 1. 现象

- AI 会话（ZCode Git Bash 沙箱）中任何原生 Windows exe（git/python/py/cmd/pwsh）启动即"挂起"；MSYS 工具（ls/cp/mv/find/grep）正常。
- `git --version` 同样挂起——与网络、仓库状态、目录中文命名均无关（ASCII 目录下对照复现过）。此前《环境基线》§4 已留档，本次定位到真正根因。

## 2. 根因（负责人定位，2026-10-24）

两个独立问题叠加，表现为"完全卡死"：

1. **主机名乱码 → git 启动 DNS 解析超时**。计算机名为中文"乔夫卡那"，`/etc/profile` 第 112 行解析出的 `HOSTNAME` 为乱码 `ÇÇ·ò¿¨ÄÇ`，hosts 文件未收录该主机名。git 启动时会解析主机名，拿着这串乱码查 DNS，查不到就一直等到超时（20~40 秒）。逐个 unset profile 变量排查：只有 `unset HOSTNAME` 有效（`git version 2.54.0.windows.1`，2,599ms 返回）；其余 12 个变量 unset 后仍卡。这也解释了"只有 git 卡、true/ls 不卡"——MSYS 程序不解析主机名，原生 Windows 程序才会。
2. **HOME=/ → PATH 出现 `//bin` → MSYS 按 SMB 路径处理**。HOME 被算成 `/`，profile 拼出 `//bin`，MSYS 把它当网络主机名 `\\bin`，每次查 PATH 慢 18 倍（16.8s vs 0.9s），登录 shell 初始化因此耗时 11.9s。

## 3. 修复内容（负责人执行）

只改 1 个系统文件 `D:\develop\tools\Git\etc\profile.d\env.sh`，追加两处补丁：

```sh
export PATH="${HOME%/}/bin:$PATH"

case "$HOSTNAME" in
  ""|*[!a-zA-Z0-9._-]*) export HOSTNAME=localhost ;;
esac
```

- 第二处为条件替换：仅当 `HOSTNAME` 含非 ASCII 字符时归一为 `localhost`；计算机名将来若改为英文，该补丁自动失效、不误伤。
- 9 份损坏的 shell 快照已用 `mv` 移至 `path_backup_2026-10-24\shell-snapshots-bak\`（未删除，可随时还原）；`env.sh` 原件同目录备份。
