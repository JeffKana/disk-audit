一、项目定义

项定稿值说明
产品名磁盘体检诊断类命名。副标题固定为"只诊断，不动手"，出现在 README 首行、安装包欢迎页、报告页眉三处
英文标识disk-auditGitHub 仓库名、发布包名均用此标识

目标用户普通 Windows 11 用户（公开发布）；开发者作为进阶用户—

语言界面与报告仅中文；README 提供英文简版文案集中在一份资源表内，预留 i18n 键名但不实现切换

二、范围

v0.1 做（In Scope）

  • 选择扫描范围：整盘（固定本地盘）或任意文件夹
  • AppData / ProgramData / 用户目录的归属判定 + 残留分级（高/中/低置信/受保护）
  • Program Files 区域只做 InstallLocation 反查，并标注"需人工确认"
  • 可再生空间分两档呈现（可再生 / 可再生但需确认）
  • 离线 HTML 报告：概览 / 明细 / 证据链 / 建议动作
  • 体检记录与两次对比（新增/减少/不变 + 净变化）
  • CSV 导出（默认脱敏）
  • 权限不足时提供"以管理员身份重扫"
  • portable + 安装包两种分发；Apache-2.0 开源

v0.1 不做（Out of Scope）

  • 任何删除 / 移动 / 重命名 / 改属性操作（永久不做）
  • 执行卸载（UninstallString 一律不调用）
  • 安装监控 / 安装快照 diff
  • 服务端、账号、云规则库、遥测、匿名统计
  • Win10 / Server / ARM64 / 可移动盘 / 网络盘
  • 常驻托盘 / 实时监控 / 定时任务
  • 自动下载并安装更新
  • 多用户、远程机器扫描（加载他人 HKCU 蜂巢）
  • 界面与报告多语言切换

三、需求条目（EARS）

每条可独立验收。U＝始终成立，E＝事件触发，S＝状态驱动，X＝异常处理。

只读与边界

[U-1] The system shall 在未获得用户显式选择的扫描范围前，不读取任何文件系统路径。 [U-2] The system shall 使本程序自身仅在 %LOCALAPPDATA%\DiskAudit\ 内发起写操作；对被扫描对象、注册表、文件属性不产生任何写操作。 [U-3] The system shall 在未获得用户显式点击的情况下，不发起任何提权请求。 [U-4] The system shall 仅通过白名单方式与系统交互：explorer.exe /select,（定位文件）、ms-settings:appsfeatures（打开系统应用列表）、写剪贴板；不调用任何安装/卸载可执行文件。

扫描与报告

[E-1] When 用户确认扫描范围，the system shall 展示实时进度（已扫描条目数、当前路径、已用时），刷新间隔不超过 500ms。 [E-2] When 扫描完成，the system shall 生成离线可打开的 HTML 报告，每条候选输出：路径、逻辑大小、占用空间、置信度、判定来源、证据链、建议动作。 [E-3] When 本次扫描与上一次体检记录存在差异，the system shall 给出"新增/减少/不变"三态对比与净变化量。 [E-4] When 扫描完成且存在因权限被跳过的条目，the system shall 在报告与启动器同时展示"未扫描条目数"，并提供"以管理员身份重扫"入口。 [E-5] When 用户在 UAC 中取消提权，the system shall 保留原报告、不重试、不弹出错误框，仅提示"已取消，结果未变更"。

判定

[S-1] While 目标命中硬保护名单（Roaming\Microsoft\Protect、Crypto、XP 兼容 Junction、系统组件），the system shall 强制标记"受保护·不可处理"，该标记不可被任何配置覆盖。 [S-2] While 判定依据仅来自启发式兜底（哈希/GUID 命名、陈旧度），the system shall 将置信度上限锁定为"低"，并提示"需人工确认"。 [S-3] While 以管理员模式扫描，the system shall 在报告显著位置标注"管理员模式"，并将结果保存为独立体检记录，不与普通记录自动对比。

异常

[X-1] If 枚举遇到权限不足、路径超长（>260）、文件被占用或 reparse point，then the system shall 跳过该项、计入"未扫描/跳过"统计、继续完成其余扫描。 [X-2] If 扫描被用户中止或异常退出，then the system shall 保留已采集的部分结果并标记"不完整报告"，不输出任何汇总结论。 [X-3] If 用户点击"检查更新"且请求失败或无网络，then the system shall 静默降级、不阻塞、不重试超过 1 次。 [X-4] If 提权进程异常退出，then the system shall 保留普通模式的既有报告，提示"管理员重扫失败，已保留上次结果"。

5.2 可再生空间两档（不使用"可回收"一词）

档位覆盖范围报告表述
可再生%TEMP%、Windows 更新缓存、崩溃转储、应用更新缓存（*-updater）、浏览器与应用缓存"可再生：应用会自行重建"

硬规则：报告不出现"可回收"字样，也不给"可释放 X GB"的合并总量。两档分别列示各自小计，总量仅呈现"磁盘占用"。理由：开发缓存对普通用户可能是在用项目的唯一依赖副本，给出合并数字即构成行为建议，与"只诊断"定位冲突。

八、安全与合规

事项定稿做法
只读边界（精确表述）本程序自身仅在 %LOCALAPPDATA%\DiskAudit\ 内写文件（U-2）。README 与报告注明：打开报告使用系统默认浏览器，浏览器自身的缓存写入不属于本程序。验证方法：Procmon 过滤 DiskAudit.exe 的 WriteFile/CreateFile 事件，交付前留档一次
提权说明提权仅用于"读取原本无权读取的目录"，提权后进程同样不写报告目录之外的位置，同样不联网、不执行卸载。UI 与 README 明确写"提权只为了看，不为了改"

隐私不收集、不上传、默认不联网。检查更新为用户手动触发，请求只带当前版本号
脱敏覆盖四类：当前用户名、计算机名、用户 SID、其他用户目录名。CSV 导出默认脱敏，报告分享前提示"报告含本机路径"并可一键生成脱敏副本

九、质量保证

9.1 三条不可协商的底线

  1. 硬保护先于一切判定：保护规则在流水线最前面短路返回，不参与打分、不可被配置覆盖（S-1）。
  2. 误判当天进回归集：任何真实误判（如原型首版把 Roaming\Code 判成 openaicodex 的子串误匹配）当日转为测试用例。
  3. 宁可漏报不可误报：README 诚实披露"可能漏掉 10~20%，但不冤枉在用软件"。

9.2 验收指标口径（消除歧义）

指标定义
判定单元扫描范围内每一个被判定的大目录（顶层目录及其下钻子项）；文件级不单独计入
自动归属率（判为"已安装/系统组件/可再生/高置信残留/中置信残留"的单元数）÷（全部判定单元数）。"低置信"与"归属未知"计入分母、不计入分子
高置信误判被判为"高置信残留"但该软件实际仍在用（存在匹配进程、自启动项或最近 30 天内有修改）的单元数，目标为 0
Ground truth 来源VM 矩阵：在快照中批量安装 N 个软件 → 用官方卸载器卸载其中 M 个 → 由此产生的残留即为已知答案。可复现、可回归
容量偏差|报告汇总占用空间 − 资源管理器同范围占用空间| ÷ 资源管理器占用空间

9.3 验收环境（VM 矩阵）

机器多样性由虚拟机提供，不使用真机。基准镜像：Windows 11 22H2 与 24H2 各一台，快照可回滚。

阶段VM 数量用途
M12 台（22H2 / 24H2 基线）容量偏差、引擎可运行性、tkinter 打包验证
M22 台（复用）提权流程、UAC 取消、断网可用性
M48 台（不同软件组合：办公 / 游戏 / 开发 / 国产全家桶 / 精简系统 等）自动归属率与误判率验收；每台先标注 ground truth 再评分
M51 台全新快照（从未运行过本程序）SmartScreen 首次运行提示留档、安装包与 portable 双形态验证
VM 方案的已知局限（记入 R10）：VM 无法替代"真人可用性测试"。因此报告文案执行零假设原则——任何可能被非开发者误解的措辞一律改保守，宁可少说。发布后通过 GitHub Issue 收集真实用户困惑，作为 v0.2 文案迭代输入。
