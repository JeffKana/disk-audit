# 判定回归样例格式 v1（待办 D6，任务卡 T2-04）

依据：方案 9.1 底线二（任何真实误判，当日转为测试用例）、开发规范 §3（判定类测试以"判定样例 JSON + 期望输出"数据驱动，样例文件与测试分离；回归样例 JSON 一律脱敏）、调研报告 `Roaming\Code` 误判 `openaicodex` 实证。

## 样例放哪里、怎么跑

- 样例文件：`tests/data/regression/R<编号>-<短横线摘要>.json`，与本 schema（`regression-case-v1.schema.json`）逐字段对应。
- 驱动方式：`tests/test_regression_cases.py` 自动加载目录内全部样例，依次执行——①schema 校验；②全文件脱敏断言；③按样例的 `path_pattern` + `unit` + `evidence_scenario`（含可选 `availability` 状态）构造纯函数输入，驱动 `disk_audit.engine.judge.judge_unit`（知识库用仓库 内 `knowledge/entries.json`），断言 `expect.confidence` / `expect.verdict_source` / `expect.forbidden_terms`。
- 新增样例只需落一个 JSON 文件，测试无需改动（数据驱动）。

## 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `case_id` | ✓ | `R` + 三位数字，递增不复用 |
| `title` | ✓ | 一句话说明锁定的误判边界 |
| `registered_at` | ✓ | 登记日期 `YYYY-MM-DD`（底线二：误判当天入集） |
| `registered_by` | ✓ | 登记来源（执行 Agent 任务卡号 / PM 复核记录） |
| `source_ref` |  | 出处引用（方案节号 / 调研报告 / 原型修复位置） |
| `root_cause` | ✓ | 误判根因 |
| `path_pattern` | ✓ | 误判路径模式；**用户名一律 `<user>` 占位** |
| `unit` | ✓ | 判定单元聚合输入（files/dirs/logical_bytes/allocated_bytes/max_mtime/exe_files，与 scan 输出 units 元素同构；`max_mtime: 0` 表示不判陈旧） |
| `evidence_scenario` | ✓ | 复现该边界所需罐装证据（uninstall/appx/processes/services/autostart 五源，与 evidence.v1 同构）；可选 `availability` 表达各源采集状态，见下节 |
| `expect` | ✓ | 期望档位 `confidence` + 期望来源 `verdict_source`（必填）；`forbidden_terms`（可选，输出全文不得出现的词，如被误判方产品名） |
| `notes` |  | 补充说明 |

## 证据源可用性 availability（可选，T6-01）

`evidence_scenario` 可带一个可选的 `availability` 对象，用来表达"该源本次不可用/未采集"，同时不改变五个证据数组本身：

| 键 | 值 | 含义 |
| --- | --- | --- |
| `uninstall` / `appx` / `processes` / `services` / `autostart` | 严格 boolean | 该证据源是否可用 |

- **只允许这五个键**（`additionalProperties: false`），值必须是 JSON boolean；`0`/`1`、`"true"`/`"false"`、`null`、数组、对象一律被 schema 拒绝，不做真假值归一。
- **缺省即旧语义**：整个 `availability` 缺省、给空对象 `{}`、或只列部分源时，未列出的源按 `true` 处理，与 R001~R005 等无该键的旧样例完全等价。
- **显式 `false` 只改状态、不丢正证据**：驱动 `_build_bundle` 把该源构造成 `available=False` 的真实 Result，样例里已给出的 `entries`/`packages`/`paths`/自启动记录仍原样保留；不得把不可用改写为"无匹配"。
- **驱动兜底**：绕过 schema 直接向驱动喂 `0`/`1`、字符串、`null`、数组或未知源键会显式报 `ValueError`，不会静默回退默认值。
- **兼容边界**：旧样例文件字节、期望与端到端判定断言均不变；本格式只增加可选表达，不改 judge/知识库/报告 schema。
- **不在本版本范围**：`reason` 文案、扫描级 `incomplete`、`admin_mode`、多 unit 表达；源不可用时的判定档位/措辞语义修复归 T5-06，不在本格式约定内。

## 脱敏规则（验收④，测试强制断言）

样例全文不得出现：真实用户名、真实计算机名、Windows SID（`S-1-5-…`）。路径中的用户目录一律 `<user>`；证据场景中的程序路径用 `C:\Program Files\…` 等通用位置或占位。

## 首例与既有样例

- `R001`：`Roaming\Code` ≠ `openaicodex`（子串误判首例，期望来源=知识库，输出全文禁现 `openaicodex`）。
- `R002`：`com.sample` 含点号包名式命名**允许**包含匹配（防护规则正向边界；避开生产 KB 已登记的 `com.example`）。
- `R003`：`abcd` 短名（<5 字符）**不参与**注册表包含匹配（防短名子串误判）。
- `R004`：`foobarcode`（≥5 字符）**允许**注册表包含匹配（规则正向边界）。
- `R005`：知识库层先于 Appx 层短路（架构③层序交互备案：`com.example` 命中 KB 即定档，Appx 层不再参与——T2-04 撰写样例时的实测发现）。
