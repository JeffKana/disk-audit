# 判定回归样例格式 v1（待办 D6，任务卡 T2-04）

依据：方案 9.1 底线二（任何真实误判，当日转为测试用例）、开发规范 §3（判定类测试以"判定样例 JSON + 期望输出"数据驱动，样例文件与测试分离；回归样例 JSON 一律脱敏）、调研报告 `Roaming\Code` 误判 `openaicodex` 实证。

## 样例放哪里、怎么跑

- 样例文件：`tests/data/regression/R<编号>-<短横线摘要>.json`，与本 schema（`regression-case-v1.schema.json`）逐字段对应。
- 驱动方式：`tests/test_regression_cases.py` 自动加载目录内全部样例，依次执行——①schema 校验；②全文件脱敏断言；③按样例的 `path_pattern` + `unit` + `evidence_scenario` 构造纯函数输入，驱动 `disk_audit.engine.judge.judge_unit`（知识库用仓库内 `knowledge/entries.json`），断言 `expect.confidence` / `expect.verdict_source` / `expect.forbidden_terms`。
- 新增样例只需落一个 JSON 文件，测试无需改动（数据驱动）。

## 字段说明

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `case_id` | ✓ | `R` + 三位数字，递增不复用 |
| `title` | ✓ | 一句话说明锁定的误判边界 |
| `registered_at` | ✓ | 登记日期 `YYYY-MM-DD`（底线二：误判当天入集） |
| `registered_by` | ✓ | 登记来源（执行 Agent 任务卡号 / PM 复核记录） |
| `source_ref` |  | 出处引用（方案节号 / 调研报告 / 原型修复位置） |
| `root_cause` | ✓ | 误判根因 |
| `path_pattern` | ✓ | 误判路径模式；**用户名一律 `<user>` 占位** |
| `unit` | ✓ | 判定单元聚合输入（files/dirs/logical_bytes/allocated_bytes/max_mtime/exe_files，与 scan 输出 units 元素同构；`max_mtime: 0` 表示不判陈旧） |
| `evidence_scenario` | ✓ | 复现该边界所需罐装证据（uninstall/appx/processes/services/autostart 五源，与 evidence.v1 同构） |
| `expect` | ✓ | 期望档位 `confidence` + 期望来源 `verdict_source`（必填）；`forbidden_terms`（可选，输出全文不得出现的词，如被误判方产品名） |
| `notes` |  | 补充说明 |

## 脱敏规则（验收④，测试强制断言）

样例全文不得出现：真实用户名、真实计算机名、Windows SID（`S-1-5-…`）。路径中的用户目录一律 `<user>`；证据场景中的程序路径用 `C:\Program Files\…` 等通用位置或占位。

## 首例与既有样例

- `R001`：`Roaming\Code` ≠ `openaicodex`（子串误判首例，期望来源=知识库，输出全文禁现 `openaicodex`）。
- `R002`：`com.sample` 含点号包名式命名**允许**包含匹配（防护规则正向边界；避开生产 KB 已登记的 `com.example`）。
- `R003`：`abcd` 短名（<5 字符）**不参与**注册表包含匹配（防短名子串误判）。
- `R004`：`foobarcode`（≥5 字符）**允许**注册表包含匹配（规则正向边界）。
- `R005`：知识库层先于 Appx 层短路（架构③层序交互备案：`com.example` 命中 KB 即定档，Appx 层不再参与——T2-04 撰写样例时的实测发现）。
